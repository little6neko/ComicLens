# 设置分区与漫画代理设计

## 背景

设置页目前将 OCR、翻译和代理字段放在同一个“OCR 与翻译”分区中，字段较多且职责混杂。代理字段仍使用“回退代理”命名，漫画源先直连，只有遇到可重试错误时才改用该代理。

ComicLens 的漫画源客户端当前明确关闭 httpx 环境代理，OCR 与翻译共享的客户端则使用 httpx 默认行为。期望改为：应用内代理只控制漫画流量；未配置应用代理时，漫画、OCR 和翻译都可以自然遵循标准代理环境变量。

## 目标

- 将设置页拆分为职责明确的 OCR、OCR 长图高级设置、翻译和代理四个分区。
- 将“回退代理”改为“漫画代理”，删除所有公开和内部字段中的 `fallback` 命名。
- 配置漫画代理后，所有漫画源请求只使用该代理，不再先直连或失败后回退。
- 未配置漫画代理时，让 httpx 自动决定使用环境代理或直连。
- OCR、DeepL 和 DeepLX 不读取应用内漫画代理，但继续支持标准代理环境变量。
- 直接丢弃数据库中旧的回退代理值，不增加旧值复制逻辑。

## 非目标

- 不增加 OCR 或翻译专用代理字段。
- 不在应用代码中解析 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY`。
- 不实现代理连通性测试、代理自动切换、代理池或每个漫画站点单独配置。
- 不更改现有请求重试次数、OCR 协议、鉴权方式或翻译服务语义。
- 不保留旧 API 字段 `fallbackProxyUrl` 的兼容别名。

## 设置页结构

设置表单继续统一提交并在底部保留一个“保存全部设置”按钮。相关分区顺序调整为：

1. **OCR**
   - 源语言；
   - OCR 模式；
   - OCR 鉴权及凭据；
   - OCR API URL；
   - OCR 模型；
   - 轮询间隔、总超时和并发。
2. **OCR 长图高级设置**
   - 保持默认折叠；
   - 长图阈值、OCR 分片高度、重叠和兼容阅读分片高度。
3. **翻译**
   - 翻译服务；
   - DeepL API Key 或 DeepLX URL；
   - 翻译超时和并发。
4. **代理**
   - 唯一字段命名为“漫画代理 URL”；
   - 提示其覆盖漫画目录、搜索、详情、章节和源图请求；
   - 提示留空时使用标准代理环境变量；
   - 明确 OCR 与翻译不使用该字段。

版本、阅读、缓存和服务器分区的内容及相对职责不变。代理分区位于翻译之后、缓存之前。

## 配置模型与命名

设置名称统一改为：

| 层级 | 新名称 |
| --- | --- |
| 数据库 / Python | `proxy_url` |
| API JSON | `proxyUrl` |
| 前端领域类型 | `proxyUrl` |
| UI 标签 | 漫画代理 URL |
| 初始环境变量 | `COMICLENS_PROXY_URL` |

`proxy_url` 继续作为敏感设置加密存储，公开设置接口只返回是否配置及掩码，不返回明文。`COMICLENS_PROXY_URL` 仍只为首次初始化或设置结构重建提供初值；运行期以数据库设置为准。

### 设置结构升级

设置结构版本从 4 提升到 5，并使用现有通用设置重建流程：

- 从设置定义中删除 `fallback_proxy_url`；
- 新增默认空值的敏感设置 `proxy_url`；
- 不编写 `fallback_proxy_url` 到 `proxy_url` 的值复制分支；
- 通用重建会删除旧行，并按新定义创建 `proxy_url`；
- 若升级时环境中存在 `COMICLENS_PROXY_URL`，它可作为新字段初值，否则新值为空。

这意味着其他部署中曾保存的旧回退代理值会被有意丢弃。当前目标部署从未设置该值，因此不需要兼容迁移。

## 网络路由

### 漫画源

每个漫画源请求开始时读取当前数据库中的 `proxy_url`：

- **非空**：为本次请求选择显式代理客户端，并关闭该客户端的环境代理读取。请求、内部重试和安全重定向全部使用同一个显式代理；失败后不尝试直连。
- **为空**：使用漫画源的常驻客户端，并启用 httpx 的环境代理读取。httpx 根据标准环境变量和 `NO_PROXY` 自行决定使用代理还是直连。

该选择覆盖漫画首页、列表、搜索、分类、排行、作者/画师归档、漫画详情、章节清单、站点地图以及源图片。源图仍通过 `ComicSource.fetch_media` 获取，因此与目录接口遵守同一规则。

设置提供器在每次请求时读取当前值，所以保存漫画代理后，新请求立即使用新线路；已经发出的请求继续使用开始时选定的线路。

### OCR 与翻译

OCR、DeepL 和 DeepLX 继续使用翻译管理器共享的 httpx 客户端。该客户端启用环境代理读取，但从不接收或查询 `proxy_url`。

因此最终路由矩阵为：

| 漫画代理设置 | 标准代理环境变量 | 漫画源 | OCR / DeepL / DeepLX |
| --- | --- | --- | --- |
| 已设置 | 已设置 | 只走应用内漫画代理 | 由环境变量与 `NO_PROXY` 决定 |
| 已设置 | 未设置 | 只走应用内漫画代理 | 直连 |
| 未设置 | 已设置 | 由环境变量与 `NO_PROXY` 决定 | 由环境变量与 `NO_PROXY` 决定 |
| 未设置 | 未设置 | 直连 | 直连 |

应用代码不读取或合并标准代理环境变量；这一行为完全由 httpx 的 `trust_env` 机制提供。

## 重试与错误处理

- 现有连接超时、网络错误、HTTP 429 和 5xx 重试策略保留。
- 一次逻辑请求的全部重试始终使用最初选定的同一条线路。
- 显式漫画代理失败后，返回现有安全的漫画源错误，不降级到直连。
- 环境代理无效时遵循 httpx 的标准失败行为，不增加应用级线路切换。
- API 和日志不得暴露含用户名、密码或 Token 的代理 URL。
- 设置保存和掩码行为沿用现有敏感字段机制。

## 组件边界

- `SettingsService` 负责新字段定义、版本 5 重建和敏感值读取。
- `Manga18fxSource` 只负责在显式漫画代理客户端与启用环境代理的常驻客户端之间选择，不了解 OCR 或翻译。
- `TranslationManager` 只为 OCR 和翻译提供启用环境代理的共享客户端，不读取漫画代理设置。
- 设置页只重排现有字段并将 `proxyUrl` 作为敏感字段提交，不实现网络选择逻辑。

这些边界保证修改应用内漫画代理不会改变正在运行的 OCR 或翻译客户端，也不会把漫画代理凭据传给第三方 OCR/翻译服务。

## 测试与验收

### 后端

- 显式漫画代理存在时，漫画 HTML、数据接口和源图只调用代理客户端。
- 显式代理请求失败后不调用常驻客户端或直连。
- 内部重试与重定向保持在选定客户端上。
- 漫画代理为空时，常驻漫画客户端启用 `trust_env`。
- OCR、DeepL 和 DeepLX 的共享客户端启用 `trust_env`，且不读取 `proxy_url`。
- 未提供 `COMICLENS_PROXY_URL` 时，设置版本 4 升级到 5 后旧 `fallback_proxy_url` 行消失，新 `proxy_url` 为空；即使旧值非空也不复制。
- `COMICLENS_PROXY_URL` 仍可为新安装或重建后的 `proxy_url` 提供初值。
- 设置 API 只公开 camelCase `proxyUrl`，不再出现 `fallbackProxyUrl`。
- 完整 pytest 和 Ruff 通过。

### 前端

- 设置页按 OCR、OCR 长图高级设置、翻译、代理顺序显示。
- OCR 长图高级设置仍默认折叠。
- 条件字段保持原行为：OCR Bearer/Basic、DeepL/DeepLX 按选择显示。
- “漫画代理 URL”保留、替换和清除操作与其他敏感字段一致。
- 桌面和手机宽度下分区、字段和统一保存按钮布局正常。
- 格式检查、Lint、TypeScript 检查和生产构建通过。

## 验收标准

1. 设置页不再出现“OCR 与翻译”或“回退代理”字样。
2. 应用内漫画代理非空时，所有漫画源请求只走该代理，失败不直连。
3. 应用内漫画代理为空时，漫画请求自动遵循标准代理环境变量或直连。
4. OCR 和翻译从不使用应用内漫画代理，但仍可由标准环境变量代理。
5. 旧 `fallback_proxy_url` 被删除且值不迁移，API 和前端只使用 `proxyUrl`。
6. 所有后端、前端和响应式布局验证通过。
