# ComicLens 流式切片队列设计

## 目标

缩短一话翻译从点击按钮到首个译图分片出现的等待时间，并修复
`useOcrForImageBlock` 导致图片区域被当作大文本框覆盖的问题。

新任务必须具备以下行为：

- OCR 默认切片高度为 `1600px`，相邻切片重叠 `200px`。
- PaddleOCR 请求不再发送 `useOcrForImageBlock`。
- 第一张源图获取并切片完成后立即开始 OCR、翻译和渲染，不等待整话源图准备完成。
- 后续源图继续按章节顺序获取、切片，并将新发现的分片追加到当前任务总数。
- 进度只保留一级分片进度，允许分母动态增长，例如 `3/5` 变为 `3/10`。
- 分片严格按页码和页内顺序处理，不进行随机或乱序 OCR。
- 普通暂停、强制停止和服务重启后仍能从持久化断点恢复。
- 部署本版本时删除现有翻译派生缓存和对应失效记录，但保留封面及原始漫画缓存。

## 已验证依据

对同一张 `720×3940` 漫画切片进行过两组对照：

- 整图且启用 `useOcrForImageBlock` 时，PaddleOCR 返回两个标签为 `image` 的大框，
  分别覆盖约 22.9% 和 42.2% 的图片。
- 整图不发送该参数时，大框消失，但只得到 3 个文本框。
- 将图片拆成 3 个约 `1400–1550px`、带重叠的切片且不发送该参数时，得到
  13 个文本框，主要对白完整识别，并且没有大面积覆盖框。

因此默认采用更小切片与重叠上下文，而不再要求 OCR 对整个图片块进行识别。

## 总体架构

单话翻译仍只有一个章节 worker，但 worker 内部拆为两个协作流程：

1. **准备生产者**按页码顺序获取源图、规范化、切片并持久化。
2. **分片消费者**按 `global_index` 顺序执行 OCR、翻译、渲染和发布。

两者并行运行，通过数据库中的分片记录交接工作，并使用进程内事件通知消费者有新分片
可用。数据库是事实来源，事件只用于避免空轮询；服务重启后不依赖内存事件恢复状态。

不为每张图建立独立 worker，也不并发消费多个分片。这样可保持当前 OCR/翻译顺序、
暂停语义和渐进展示顺序不变。

## 准备生产者

生产者按章节清单顺序处理尚未准备的页面。每页执行：

1. 优先读取永久保留的原始漫画缓存；缺失时从来源获取。
2. 规范化为 PNG，并保存原始图片及校验值。
3. 使用当前任务语义设置规划 OCR 切片，默认目标高度 `1600px`、重叠 `200px`。
4. 将该页所有 OCR 输入切片写入 generation 缓存目录。
5. 在单个数据库事务中标记该页已准备、插入该页全部分片，并把
   `total_segments` 增加该页切片数。
6. 通知消费者有新分片可用，然后继续处理下一页。

页面只有在该页所有切片文件成功写入后才会被标记为已准备。若进程在数据库提交前中断，
重启后会重新检查并复用完整的切片文件；若数据库提交完成，则不会为该页重复追加记录。

`global_index` 按页码及页内 `segment_index` 单调递增。追加事务以当前 generation
已有最大值为起点，并拒绝重复的 `(generation_id, page_index, segment_index)`。

所有页面准备完成后，生产者将 `planning_complete` 设为真并再次通知消费者。

## 分片消费者

消费者启动后反复读取当前 generation 中 `global_index` 最小的待处理分片：

- 有待处理分片：完成 OCR、翻译、渲染和原子发布，再处理下一片。
- 暂时没有待处理分片且 `planning_complete=false`：等待生产者通知。
- 没有待处理分片且 `planning_complete=true`：汇总页面状态并结束 generation。

消费者不会等待生产者处理第二张图。第一张图的追加事务完成后，它即可开始第一片 OCR，
此时生产者继续获取和切分第二张图。

失败分片沿用现有行为：记录失败原因并继续下一片；失败数不计入完成数。只有分片完成
OCR、翻译、渲染并发布后，`completed_segments` 才加一。

## 动态进度

`total_segments` 表示当前已经切分并持久化的分片数，不再表示只有整话规划完毕后才可用的
最终总数。其变化示例：

1. 第一张图切出 5 片：`0/5`。
2. 前 3 片完成：`3/5`。
3. 第二张图又切出 5 片：`3/10`。
4. 所有页面准备完成后，分母停止增长，最终到达 `10/10`。

阅读器顶部和设置页后台任务卡片只要 `total_segments > 0` 就显示分片进度，不再要求
`planning_complete=true`。规划尚未完成时仍显示源图准备数量，提示当前分母可能继续增长。
百分比允许因分母增长而下降，这是动态发现工作量的正常表现。

## 状态、暂停与恢复

- generation 初始为 `preparing`。
- 第一批分片可消费后进入 `running`，即使 `planning_complete` 仍为假。
- 普通暂停会阻止生产者开始下一页，并让消费者完成当前分片后进入 `paused`。
- 强制停止会取消生产者和消费者；正在执行的分片回滚为可恢复的待处理状态，已提交的页面、
  分片和检查点保留。
- 服务启动恢复时，已准备页面不重复追加；未准备页面继续生产；未完成分片继续按
  `global_index` 消费。
- 只有 `planning_complete=true` 且不存在待处理分片时才能将 generation 标记为完成或
  部分失败，避免消费者在生产者暂时没有新分片时提前结束。

普通暂停发生在源图下载或切片期间时，当前页面允许完成持久化，之后不再开始下一页。
这避免留下数据库已准备但切片文件不完整的页面。强制停止仍可立即取消当前准备操作。

## OCR 请求与版本隔离

PaddleOCR multipart 的 `optionalPayload` 只包含：

```json
{
  "useDocOrientationClassify": false,
  "useDocUnwarping": false,
  "useChartRecognition": false
}
```

不得发送 `useOcrForImageBlock`，包括值为 `false` 的形式；对照测试采用的就是字段完全缺失。

流水线语义版本升级，切片高度、重叠和 OCR 可选参数继续进入语义指纹。新版本不会匹配或
复用旧参数生成的 generation。

设置默认值更新为 `1600/200`。设置迁移只把仍等于旧默认值 `4000` 的 OCR 切片高度更新为
`1600`；其他自定义高度保留，重叠自定义值也保留。当前服务器使用旧默认值时会随迁移切换
到新默认值。

## 缓存清理

代码及测试验证完成后，先停止 ComicLens 服务及活动翻译任务，再进行一次有边界的清理：

- 删除 `data/cache/chapters/*/generations/` 下的 OCR 输入切片、OCR JSON、文本块、翻译文本、
  译图分片及其他 generation 派生文件。
- 删除这些 generation 对应的缓存索引和翻译任务记录，清除活动译图引用，避免页面或
  “重新翻译”错误复用已删除路径。
- 保留 `data/cache/chapters/*/originals/`、`data/cache/covers/`、阅读历史、收藏、应用设置、
  OCR Token 和翻译服务配置。

清理前后记录文件数量和缓存占用。目标必须解析为具体的 `generations` 目录和关联数据库
记录，不对整个 `data/cache` 或项目目录执行递归删除。

清理后重新启动服务。之后用户再次触发翻译时，任务会从永久保留的原始漫画缓存重新按
新逻辑切片，因此无需重新从 Manga18fx 下载已有原图。

## 错误处理

- 页面获取或切片失败：保留已完成分片和已准备页面，generation 标记失败；再次启动同一
  语义任务时从未准备页面继续。
- OCR、翻译或渲染失败：沿用分片级失败与点击重试能力。
- 生产者异常：通知等待中的消费者退出，避免消费者永久等待。
- 消费者异常：取消生产者并保留已提交断点，避免后台继续无消费者地下载整话。
- 数据库追加失败：不增加 `total_segments`；缓存中的孤立切片可在重试时复用或由缓存上限
  清理。

## 测试与验收

后端测试至少覆盖：

- 默认设置为 `1600/200`，旧默认值迁移为 `1600`，自定义值不被覆盖。
- OCR multipart 中不存在 `useOcrForImageBlock`。
- 第二张源图被阻塞时，第一张图的首片已进入 OCR，证明不等待整话准备。
- 第一页追加后总数为 5，消费者完成 3 片后为 `3/5`，第二页追加后变为 `3/10`。
- 分片始终按 `global_index` 处理和发布。
- 规划未完成且暂时无待处理分片时不会提前完成任务。
- 普通暂停、强制停止和服务重启均可继续未准备页面及未完成分片，不重复追加。
- 页面准备失败及分片失败保留已有进度并可恢复。

前端验收包括：

- 阅读器顶部在规划未完成但已有分片时显示动态 `完成数/当前总数`。
- 设置页后台任务同时显示源图准备数和动态分片进度。
- 分母增加时 UI 正常更新，不隐藏进度条或误报完成。

最后运行完整后端测试、前端 lint 和生产构建，并确认服务继续监听 `0.0.0.0:8233`。
