# ComicLens GHCR v0.1.2 发布设计

## 目标

沿用 `v0.1.1` 的完整补丁发布方式，将已经完成并验证的“成功打开章节即标记已读”修复发布为
ComicLens `v0.1.2`：

- 统一后端、前端、Python 包、Docker 镜像默认元数据、测试契约和部署示例版本；
- 将当前尚未推送的已读修复设计、实现记录和代码连同 release commit 推送到 `main`；
- 使用轻量标签 `v0.1.2` 触发现有 GitHub Actions；
- 发布 `linux/amd64` 与 `linux/arm64` 的 GHCR 镜像；
- 让 `ghcr.io/little6neko/comiclens:v0.1.2` 与 `latest` 指向同一多架构索引。

本次不创建 GitHub Release，不修改发布 workflow，不连接、部署或重启远程服务器，不迁移数据库，
也不清理用户数据或缓存。用户已要求测试服务停止，发布完成后继续保持停止。

## 当前状态

- 编写本发布设计前，`main` 与 `origin/main` 没有分叉，本地领先 3 个已读修复相关提交：设计、
  实施记录和实现；本设计将作为独立文档提交追加在其后。
- 上述已提交内容的作者均为 `little6neko <little6carbon@163.com>`。
- 现有发行标签为 `v0.1.0` 和 `v0.1.1`；本地与远端均不存在 `v0.1.2`。
- 当前应用版本入口均为 `0.1.1`。
- `.github/workflows/publish-image.yml` 只响应 `v*.*.*` 标签，构建
  `linux/amd64,linux/arm64` 并输出原始版本标签和 `latest`。
- 本机没有 Docker、Podman、Buildah、GH CLI 或独立 registry inspect 工具。
- 本地 `0.0.0.0:8233` 测试服务已经停止。

## 版本统一

下列入口从 `0.1.1` 更新为 `0.1.2`：

- `pyproject.toml` 的项目版本；
- `app/__init__.py` 的 `__version__`；
- `tests/test_app.py` 的健康接口版本契约；
- `web/package.json` 与 `web/package-lock.json` 的根包版本；
- `web/src/lib/version.ts` 的设置页可见版本；
- `Dockerfile` 的默认 `VERSION` build argument；
- README 中固定镜像版本和升级变量。

README 的 `latest` 一般说明保留。历史设计和实施文档中的旧版本是已发生事实，不机械替换。
workflow 继续从 Git tag 生成镜像标签，不硬编码 `v0.1.2`。

## 验证门槛

创建 release commit 前必须通过：

1. `git diff --check`；
2. `ruff check .`；
3. 完整后端 `pytest`；
4. 前端格式检查、lint、独立 `tsc --noEmit` 和生产构建；
5. Python 模块、项目元数据、健康接口、OpenAPI、前端 package/lock 和版本常量均为 `0.1.2`；
6. 使用临时源码副本构建 wheel，确认 METADATA 版本为 `0.1.2`；
7. 前端生产构建产物包含 `0.1.2` 且不包含旧应用版本；
8. 非历史文件不存在仍指向 `v0.1.1` 的当前部署示例；
9. workflow 内容和 tag 触发条件保持不变；
10. 测试服务仍未监听 `8233`。

本机缺少容器运行工具，不安装或修改主机环境。本地无法执行 Docker build，因此 GitHub Actions
的真实 Buildx 双架构构建与 GHCR manifest 检查作为最终容器门禁。

## 提交、推送与标签顺序

全部本地门禁通过后：

1. 创建 `chore: release v0.1.2`，作者与提交者均使用指定身份；
2. 确认工作区干净；
3. 重新 fetch，确认 `origin/main` 没有新增提交，远端仍不存在 `v0.1.2`；
4. 先非强制推送 `main`；
5. 确认远端 `main` 与 release commit 一致；
6. 在 release commit 上创建轻量标签 `v0.1.2`；
7. 单独非强制推送标签，触发 `Publish Docker image` workflow。

不使用 `--force`，不移动、覆盖或删除已有发行标签。

## Action 与镜像验收

标签推送后，通过 GitHub 官方 REST API 轮询正确的 tag run，直到成功或得到明确失败结果。成功后
直接使用 GHCR OCI Registry API 验证：

- `v0.1.2` 与 `latest` 均存在并解析到同一索引摘要；
- 索引包含 `linux/amd64` 与 `linux/arm64`；
- 两个平台的 `org.opencontainers.image.revision` 均为 release commit；
- 现有 metadata workflow 生成的 OCI version label 为带 `v` 的 `v0.1.2`；
- OCI source 指向 `https://github.com/little6neko/ComicLens`。

应用内部、Python/前端包和健康接口版本使用不带 `v` 的 `0.1.2`；Git 标签与 metadata-action 的
镜像版本标签使用 `v0.1.2`，两者含义一致。

## 失败处理

- 本地验证失败：停止发布，不创建 release commit 或标签，修复后重新运行相关完整门禁。
- `main` 推送失败或远端分叉：不创建标签，先核对远端状态。
- 远端已存在 `v0.1.2`：停止，不覆盖、不删除、不移动。
- 标签推送后 Action 失败：保留不可变标签和失败记录，不重推或改写；后续使用新的补丁版本修复。
- GHCR 暂时不可见：等待注册表同步并重复只读检查，不重复推送标签。

## 验收结果

发布完成时：

- `main`、`origin/main` 和轻量标签 `v0.1.2` 指向同一 release commit；
- Git 工作区干净，发布相关提交作者正确；
- GitHub Action 成功；
- `v0.1.2` 与 `latest` 多架构镜像通过摘要、平台和 OCI 标签验收；
- 本地测试服务保持停止，远程部署没有任何变更。
