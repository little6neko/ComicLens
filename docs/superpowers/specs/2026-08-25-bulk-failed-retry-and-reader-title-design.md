# 批量重试失败项与阅读器章节标题设计

## 背景

ComicLens 目前提供两种恢复操作：阅读器右上角的“重新翻译本话”会重新处理整话，失败分片上的“重新翻译”只重试一个分片。设置页后台任务卡只提供“强制停止”，没有批量恢复入口。

这使多个分片失败时只能逐个点击，或者重新调用 OCR、翻译和渲染已经成功的分片。设置页还只返回活动任务；任务结束为 `completed_with_errors` 后任务卡立即消失，用户无法从设置页恢复失败项。

阅读器副标题使用章节页面 HTML 标题。上游标题通常包含漫画名，例如 `Alpha Comic Chapter 12`，与第一行漫画名重复并占用过多空间。

## 目标

- 为每一话提供“一键重试所有失败项”，成功项保持不动。
- 阅读器和设置页共用一个章节级批量重试接口。
- 批量重试覆盖 OCR、翻译、渲染和缓存失败，并从每项正确的检查点继续。
- 当前正在执行的分片不被取消；重新入队项继续使用现有全局序号调度。
- 设置页同时提供“全部重试”“重试失败”，并保留尚有失败的终态任务卡。
- 阅读器副标题改用章节列表标题，并将开头的 `Chapter` 缩写为 `Ch.`。

## 非目标

- 不增加跨章节的全局“全部重试”按钮。
- 不实现定时自动重试或新的优先级队列。
- 不为失败项创建独立 generation。
- 不移除现有单片重试、整话重译、暂停或强制停止能力。
- 不改变 OCR 协议、鉴权或凭据存储方式。
- 不为本次前端改动额外引入单元测试框架。

## 用户可见语义

### 三种恢复操作

- “重新翻译本话”或设置页“全部重试”：成功和失败项全部重新处理，继续使用现有整话重译接口和确认提示。
- “重试失败”：将当前话在点击时仍为 `failed` 的全部项重新加入现有 generation，无确认提示。
- 分片失败区域的“重新翻译”：继续只重试该分片。

“重试失败”请求期间按钮禁用并显示加载状态。成功后提示“已加入 N 个失败项”；若其他请求已先完成重试，则返回 N 为零，不报冲突。

### 调度顺序

批量重试不会取消当前正在执行的 OCR、翻译或渲染。失败项改回 `pending` 后继续按 `global_index` 从小到大参与调度。因此当前执行到较后分片时重试较早失败分片，当前分片先安全完成，较早失败项在后续调度点优先进入串行后处理。OCR 预取仍受全局 OCR 并发限制；出现空闲许可时，较早失败项可以在当前分片结束前开始 OCR，但已有 OCR 请求不被取消。

## API 设计

新增接口：

`POST /api/comics/{comic_id}/chapters/{chapter_id}/translation/retry-failed`

请求不需要正文。响应模型包含：

- `task`：操作后的 `TranslationTaskState`；
- `retriedCount`：本次从 `failed` 改回待处理的项数。新分片 generation 统计分片，旧版无分片 generation 统计页面。

该接口使用与开始、整话重译、单片重试和强制停止相同的章节操作锁。它定位该话最新 generation，并遵守以下错误语义：

- 没有翻译任务时返回 404；
- generation 正在 `stopping_after_page` 或 `stopping_after_segment` 时返回 409，不改变任务；
- 没有失败项或重复调用时返回 200，`retriedCount` 为零；
- 数据库操作失败时整批回滚，保留原失败状态。

前端通常在停止状态提前禁用重试按钮，因此 409 主要用于处理竞态和直接 API 调用。

## 批量检查点恢复

批量重试和现有单片重试必须共用一套阶段策略，避免入口不同导致缓存复用行为不同。

| 失败阶段 | 保留 | 清除并重做 | 异步 OCR job ID |
| --- | --- | --- | --- |
| OCR | 源图、OCR 输入 | OCR 响应、文本块、翻译、译图 | 清除，下一次提交新任务 |
| 翻译 | 源图、OCR 响应、文本块 | 翻译、译图 | 保留但不再使用远端 OCR |
| 渲染 | 源图、OCR 响应、文本块、翻译 | 译图 | 保留 |
| 缓存 | 源图、OCR 响应、文本块、翻译 | 译图 | 保留 |

Repository 在一个数据库事务中：

1. 按原始全局序号读取目标 generation 的所有 `failed` 项；
2. 根据每项 `error_stage` 清空对应路径、版本和安全错误字段；
3. 将项状态改为 `pending`；
4. 将受影响页面改为 `pending` 并清理页面汇总错误；
5. 统一刷新 generation 的完成数和失败数。

事务返回已经失效的缓存路径，由 Manager 在提交后尽力删除。缓存文件删除失败只记录日志，不把已经成功提交的批量操作改报为失败。数据库不再引用这些路径，因此后续执行不会把旧文件误认为有效检查点。

新式 progressive generation 只批量恢复失败分片。若 generation 没有分片计划，则使用同一阶段策略批量恢复旧版失败页面，避免旧缓存任务失去恢复入口。

## generation 与 worker 状态

- `preparing`、`queued`、`running`：保持活动状态，不打断当前项；唤醒 streaming generation 的事件并确保章节 worker 存在。
- `paused`、`completed_with_errors`：恢复同一 generation，不创建新的整话任务，然后启动 worker。
- `failed`：存在明确 `failed` 项时恢复同一 generation；没有可批量恢复项时返回零，用户可使用“全部重试”。
- `stopping_after_page`、`stopping_after_segment`：拒绝批量重试并返回 409。

批量重试不改变 generation 的 `kind`，也不新增数据库表或迁移。

## 设置页后台任务列表

后台任务接口继续每话最多返回一张任务卡，并扩展为：

- 返回现有活动状态；
- 若一话没有活动 generation，且该话最新 generation 的状态是 `completed_with_errors`，则保留该 generation；
- 若最新 generation 整体为 `failed`，也保留任务卡，至少提供整话“全部重试”；
- 活动 generation 优先于同话较旧的终态失败 generation，避免重复卡片；
- generation 成功完成且失败数归零后，任务卡自动从该区域消失。

终态失败卡使用明确的“等待重试”阶段标签。设置区摘要分别显示正在处理的话数和等待重试的话数；只有存在活动任务时才显示全局加载图标。

### 任务卡布局

使用已确认的 B 布局：

- 标题区放置“全部重试”；活动任务同时保留“强制停止”；
- “重试失败”紧邻失败数量和进度信息；
- `failedSegments` 或兼容的 `failedPages` 为零时隐藏“重试失败”；
- 停止中的任务禁用恢复操作；
- 终态失败卡不显示“强制停止”。

“全部重试”复用现有 `retranslate` API 和成本确认弹窗。“重试失败”调用新接口，不显示确认弹窗。两种操作成功后均更新后台任务查询和对应章节任务查询；失败使用现有安全 toast，不暴露缓存路径、远端结果地址或凭据。

## 阅读器界面

阅读器顶栏右侧操作顺序为：

1. 现有“实时翻译”开关；
2. 有失败时显示的“重试失败”；
3. 现有“重新翻译本话”。

桌面宽度允许时，“重试失败”显示文字和失败数；窄屏显示重试图标与失败数，并提供完整 `aria-label` 和 `title`。失败数为零时隐藏该按钮，避免增加常态顶栏宽度。正在停止或批量请求尚未结束时按钮禁用。

点击阅读器“重试失败”会开启本地译图模式，调用新接口，并把返回的 `task` 立即写入 React Query 缓存。失败区域因此在下一次渲染中由“失败”切换成“翻译中”，无需等待一秒轮询。现有单片重试按钮继续保留。

## 阅读器章节副标题

顶栏第一行继续显示漫画名。副标题不再使用 `manifest.title`，而是从 `ComicDetail.chapters` 中按当前 `chapterId` 找到章节标题。

格式化规则：

- 去除标题首尾空白；
- 仅将开头、完整单词且不区分大小写的 `Chapter` 替换为 `Ch.`；
- 保留章节号、分隔符和真实章节名的其余文本；
- `Chapter 12` 显示为 `Ch. 12`；
- `Chapter 12: Awakening` 显示为 `Ch. 12: Awakening`；
- 非 `Chapter` 开头的本地化标题保持原样；
- 若详情中找不到当前章节，则从 `chapterId` 生成简短回退值：`chapter-12` 显示为 `Ch. 12`，其他格式直接显示原 ID；不再回退到可能包含漫画名的 `manifest.title`。

该格式化只用于阅读器顶栏，不改变上游目录数据、章节 URL 或后端 manifest。

## 并发与幂等

- 章节操作锁串行协调批量重试、整话重译、暂停和强制停止。
- Repository 只更新提交时仍为 `failed` 的项；同一操作的第二个请求不会重复清理或增加尝试次数。
- 当前 worker 已经持有的分片不符合 `failed` 条件，因此不受批量事务影响。
- streaming generation 在事务完成后被显式唤醒，以便空闲 OCR 许可及时拾取重试项。
- 多个章节仍使用各自 worker；批量重试一话不会取消或暂停其他章节。

## 测试与验收

### 后端自动测试

- 混合 OCR、翻译、渲染和缓存失败一次性恢复，逐项验证保留和清除的检查点。
- 当前正在处理较后分片时重试较早失败分片，验证当前项没有取消，并验证后续处理顺序按 `global_index`。
- OCR 并发预取不取消已有请求，重试 OCR 只在许可可用时启动。
- `completed_with_errors` 和 `paused` 恢复同一 generation。
- 重复请求第一次返回实际数量，第二次返回零。
- 停止状态返回 409；无任务返回 404。
- 旧版页面级失败可以批量恢复。
- 后台任务列表保留终态失败任务、活动任务覆盖同话旧卡、成功完成后移除卡片。
- API 返回 `task` 和 camelCase `retriedCount`。

### 前端和集成验收

- 运行前端格式检查、Lint、TypeScript 检查和生产构建。
- 确认阅读器三个操作在桌面和窄屏不重叠，隐藏、禁用和加载状态正确。
- 确认设置页运行中与等待重试任务卡使用 B 布局。
- 确认章节副标题的无名称和带名称示例。
- 使用临时数据目录在 `0.0.0.0:8233` 启动最新构建，验证健康接口、设置路由和阅读器 UI；不写入或调用用户的线上 OCR 凭据。
- 最后运行完整 pytest 与 Ruff，并保持工作区无意外文件。

## 验收标准

1. 一次点击可以重新入队当前话点击时全部失败的分片或兼容页面，成功项和当前执行项不受影响。
2. 重试项使用正确检查点，OCR 失败会提交新 job，后续阶段失败不重复 OCR。
3. 阅读器和设置页都能执行批量失败重试；设置页还能执行整话全部重试。
4. 设置页持续显示尚未解决的终态失败任务，失败清零后自动移除。
5. 所有按钮在停止、请求中、无失败和终态任务状态下显示及禁用正确。
6. 阅读器章节副标题不再重复漫画名，并按约定显示 `Ch.`。
7. 后端完整测试、Ruff、前端格式检查、Lint 和生产构建全部通过。
