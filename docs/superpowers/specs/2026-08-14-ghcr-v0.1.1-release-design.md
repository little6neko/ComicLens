# ComicLens GHCR v0.1.1 发布设计

## 目标

沿用 `v0.1.0` 的发布方式，将已经完成并验证的全服务动态 OCR 并发功能发布为
ComicLens `v0.1.1`：

- 统一后端、前端、Python 包、Docker 镜像元数据和部署示例的版本号；
- 将当前尚未推送的 OCR 并发相关提交连同 release commit 推送到 `main`；
- 使用轻量标签 `v0.1.1` 触发现有 GitHub Actions；
- 发布 `linux/amd64` 与 `linux/arm64` 的 GHCR 镜像；
- 让 `ghcr.io/little6neko/comiclens:v0.1.1` 与 `latest` 指向同一多架构版本。

本次不创建 GitHub Release，不修改发布 workflow，不部署或重启远程服务器，也不迁移数据库或
清理缓存。

## 当前状态

- 编写本发布设计前，`main` 比 `origin/main` 领先 7 个已提交的 OCR 并发设计、计划、实现和
  测试提交；本设计将作为独立文档提交追加在其后。
- 上述已提交内容的作者均为
  `little6neko <little6carbon@163.com>`。
- 当前唯一发行标签为 `v0.1.0`。
- 当前应用版本入口均为 `0.1.0`。
- `.github/workflows/publish-image.yml` 已配置为只响应 `v*.*.*` 标签，并构建
  `linux/amd64,linux/arm64`，输出版本标签和 `latest`。
- 本地测试服务正在 `0.0.0.0:8233` 运行；发布过程不停止它。文件版本更新不会改变已经启动的
  进程，只有将来重新启动后本地服务才会报告 `0.1.1`。

## 版本统一

下列入口从 `0.1.0` 更新为 `0.1.1`：

- `pyproject.toml` 的项目版本；
- `app/__init__.py` 的 `__version__`；
- `web/package.json` 与 `web/package-lock.json` 的根包版本；
- `web/src/lib/version.ts` 的设置页可见版本；
- `Dockerfile` 的默认 `VERSION` build argument；
- README 中固定使用 `v0.1.0` 镜像的拉取、运行和 Compose 示例。

README 仍可保留 `latest` 的一般说明，但所有不可变版本示例改为 `v0.1.1`。历史设计和实施文档
中的 `v0.1.0` 是已发生事实，不进行机械替换。

版本号不会进入服务器设置，不需要数据库迁移。Docker workflow 继续从 Git tag 生成镜像标签，
不硬编码 `v0.1.1`。

## 验证门槛

创建 release commit 前必须通过：

1. `ruff check .`；
2. 完整后端 `pytest`；
3. 前端 lint 与格式检查；
4. 前端生产构建及 `tsc --noEmit`；
5. 本地 Docker 镜像构建；
6. 健康接口、OpenAPI 版本、Python 模块版本、前端版本常量、包元数据和 Docker label
   均为 `0.1.1`；
7. 仓库中非历史文件不存在仍指向 `v0.1.0` 的部署示例；
8. workflow 语法和 tag 触发条件保持不变。

本地 Docker 构建只验证当前主机架构。`amd64/arm64` 多架构产物由 GitHub Actions 的 Buildx
任务验证。

## 提交与标签顺序

验证通过后按以下顺序发布：

1. 创建提交 `chore: release v0.1.1`，作者为
   `little6neko <little6carbon@163.com>`。
2. 确认工作区干净，且本地与远端均不存在 `v0.1.1`。
3. 先通过 SSH remote 推送 `main`，确保 release commit 及此前 7 个功能提交进入远端分支。
4. 在 release commit 上创建轻量标签 `v0.1.1`。
5. 再单独推送 `v0.1.1`，由标签触发 `Publish Docker image` workflow。

不使用 `--force`，不移动已有标签。标签指向必须与 `origin/main` 的 release commit 一致。

## Action 与镜像验收

标签推送后等待对应 GitHub Actions run 结束，并验证：

- workflow 名称为 `Publish Docker image`，事件来源是 `v0.1.1` 标签；
- run 成功完成，而不只是成功排队；
- GHCR 存在 `ghcr.io/little6neko/comiclens:v0.1.1` 和 `latest`；
- 两个标签解析到同一镜像索引摘要；
- manifest 同时包含 `linux/amd64` 与 `linux/arm64`；
- 镜像 OCI version label 为 `0.1.1`，revision 为 release commit。

验证只读取 GitHub Actions 与 GHCR 状态，不连接或修改用户部署在
`root@oracle-sg-arm` 的 ComicLens 容器。

## 失败处理

- 任一本地验证失败：停止发布，不创建 release commit 或 tag，修复后重新完整验证。
- `main` 推送失败：不创建或推送 tag，先解决分支同步或权限问题。
- 远端已存在 `v0.1.1`：停止并核对其目标，不覆盖、不删除、不移动。
- tag 推送后 Action 失败：保留不可变标签与失败记录，不强制改写标签；诊断原因后由新的补丁版本
  或用户明确授权的恢复方案处理。
- GHCR 暂时不可见：先等待注册表同步并重复只读检查，不重复推送标签。

## 验收结果

发布完成时应满足：

- `main`、`origin/main` 与 `v0.1.1` 指向同一 release commit；
- Git 工作区干净，提交作者正确；
- GitHub Action 成功；
- `v0.1.1` 和 `latest` 多架构镜像通过验收；
- 本地测试服务仍在运行，远程部署未发生任何变更。
