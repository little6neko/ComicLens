# 设置 URL 明文与独立代理凭据设计

## 背景

ComicLens 当前把 OCR API URL 和漫画代理 URL 与 Token、密码等凭据一起加密保存。设置 API
只返回掩码状态，前端必须通过“保留 / 替换 / 清除”修改它们，无法直接查看或编辑完整 URL。

漫画代理鉴权目前只能嵌入代理 URL，例如
`http://user:password@proxy.example:8080`。本次将两个 URL 改为普通明文字段，并为漫画代理
增加独立账号和密码。代理 URL 始终按用户输入原样保存；独立凭据只在请求发生前覆盖运行时
代理地址中的凭据，不解析、拆分或重写数据库中的 URL。

## 已确认行为

- OCR API URL 和漫画代理 URL 在数据库中明文保存。
- `/api/settings` 返回两个完整 URL，设置页使用普通输入框直接显示和编辑。
- 漫画代理新增独立的账号与密码输入：账号明文保存，密码继续加密并通过掩码操作。
- 代理 URL 不做自动拆分、规范化或重写，即使其中包含账号密码也保持原字符串。
- 独立账号或密码任一非空时，运行时覆盖 URL 自带凭据；两项均为空时直接使用原 URL。
- 允许账号为空而密码非空，也允许账号非空而密码为空。
- OCR API URL 在设置页排列于“OCR 鉴权”左侧。
- 不改变漫画代理只用于漫画请求的边界，也不改变未配置漫画代理时遵循标准代理环境变量的行为。
- 不新增代理账号或密码环境变量。

## 设置数据模型

设置定义调整如下：

- `ocr_api_url`：从 secret 改为普通字符串；
- `proxy_url`：从 secret 改为普通字符串；
- `proxy_username`：新增普通字符串，默认空；
- `proxy_password`：新增 secret 字符串，默认空。

`ocr_token`、`ocr_basic_password`、`deepl_api_key`、`deeplx_url` 等其他 secret 定义保持不变。
代理账号与密码只属于漫画代理，OCR、DeepL 和 DeepLX 不读取它们。

服务端响应模型直接以字符串返回 `ocrApiUrl`、`proxyUrl` 和 `proxyUsername`；
`proxyPassword` 使用现有 `SensitiveSettingState`。PATCH 模型中两个 URL 和账号接受普通字符串，
代理密码继续使用现有 `keep / replace / clear` 操作。

普通 URL 字段允许空字符串，以保留清除配置的能力；不在本次新增 URL 格式或协议白名单校验，
避免改变现有自定义代理和 OCR 地址兼容性。账号同样允许为空。

## 数据库升级

设置 schema 版本从 `6` 提升为 `7`，完全复用现有通用重建流程，不增加字段专用迁移分支：

1. `_decode_rows` 根据旧记录的 `is_secret` 标记解密现有 OCR API URL、代理 URL 和其他 secret；
2. `_migrate_values` 复制所有仍存在于新设置定义中的旧值；
3. 新增的代理账号和密码使用空字符串默认值；
4. `_replace_settings` 根据新定义重新写入全部设置。

重建后，两个 URL 的 `is_secret` 为 `0`，值是 JSON 字符串明文；代理账号的 `is_secret` 为
`0`，代理密码为 `1` 且密文保存。其他普通与加密设置保留原值及各自的加密属性。

迁移不检查代理 URL 是否包含 userinfo，不从 URL 提取账号密码，也不清除、编码或重新序列化
URL 内容。全新数据库从一开始使用相同的新定义。

## 代理运行时凭据

设置仓储中的三个代理值保持独立：

- `proxy_url`：用户输入的原字符串；
- `proxy_username`：独立账号；
- `proxy_password`：独立密码明文，仅在服务端解密后的运行期设置中存在。

漫画来源在每次请求前读取最新设置，按以下规则生成仅供本次客户端使用的运行时代理 URL：

1. `proxy_url` 去除首尾空白后为空：不使用设置代理，维持现有环境变量或直连行为；账号密码
   此时不单独生效。
2. 账号和密码都为空：将原代理 URL 直接交给 httpx，包括原 URL 可能已有的 userinfo。
3. 账号或密码任一非空：使用 `httpx.URL` 在内存中复制代理地址，并同时设置独立账号和密码；
   空的另一项作为空凭据发送。
4. 生成的运行时 URL 不写回数据库、设置 API 或前端状态。

httpx 负责对独立账号和密码进行 URL 编码。运行时值只用于创建漫画请求的临时代理客户端，
不进入日志或用户可见错误。代理 URL 无效时沿用现有漫画上游请求错误语义，错误信息不得包含
URL、账号或密码。

保存设置后无需重启。漫画来源的 provider 每次请求读取当前值，因此 URL、账号或密码的修改
都会从下一次漫画请求开始生效。正在执行的请求不被取消。

## 设置页

OCR 区块调整为：

- OCR API URL 从 `SecretField` 改为普通 `Input`；
- 在两列设置网格中，将 OCR API URL 放在“OCR 鉴权”左侧；
- URL 输入值进入服务器设置草稿，点击“保存全部设置”后生效。

代理区块调整为三个字段：

- 漫画代理 URL：普通输入框，直接显示完整值；
- 代理账号：普通输入框，直接显示完整值；
- 代理密码：沿用 `SecretField`，支持保留、替换和清除，不回显明文。

URL placeholder 使用不含凭据的示例，但不禁止用户输入带凭据 URL。辅助文字说明独立账号或
密码会在运行时覆盖 URL 自带凭据，并继续明确该代理只用于漫画接口。设置页保存 payload 中，
URL 和账号为直接字符串，密码为敏感操作对象。

## 安全边界

两个 URL 不再视为敏感字段，因此会出现在：

- SQLite 数据库明文；
- `/api/settings` JSON 响应；
- 设置页输入框；
- 浏览器开发者工具中的设置请求和响应。

若用户继续把凭据写在代理 URL 中，这些凭据也会随 URL 明文可见。这是已确认的数据归属，
应用不做自动拆分或隐藏。建议需要隐藏密码时使用新增的独立密码字段，并通过
`COMICLENS_ACCESS_PASSWORD` 限制设置 API 访问。

独立代理密码和其他 secret 仍依赖 `secrets.key` 解密；升级不会降低这些字段的保护。公共监听
且未启用访问密码时的现有警告保持不变。

## 验证

后端测试覆盖：

- 全新数据库中两个 URL 与代理账号为明文记录，代理密码为加密记录；
- schema 6 数据库升级后保留两个 URL 的精确字符串并改为明文，不拆分 URL 自带凭据；
- 升级保留其他普通字段和 secret，设置 schema 更新为 `7`；
- GET 返回完整 URL 和账号，只掩码代理密码；
- PATCH 可直接修改或清空 URL、账号，并可保留、替换、清除代理密码；
- 独立凭据任一非空时覆盖运行时 URL 凭据，两项为空时原 URL 保持不变；
- URL、账号和密码保存后从下一次漫画请求立即生效；
- 请求失败和日志不泄漏独立凭据或带凭据 URL。

前端与工程验证覆盖：

- OCR API URL 位于 OCR 鉴权左侧并显示完整值；
- 代理区显示 URL、账号和密码三个字段；
- 保存请求直接提交 URL 与账号，代理密码仍提交敏感操作；
- 清空 URL 或账号可正常保存，密码的保留、替换、清除行为不变；
- 完整后端测试、Ruff、前端格式、Lint、TypeScript 和生产构建通过；
- 使用隔离测试数据库验证 API 响应、数据库 `is_secret` 标记和设置页构建产物。

## 非目标

- 不自动拆分、清理或重写代理 URL 中的账号密码。
- 不强制禁止带 userinfo 的代理 URL。
- 不新增代理账号或密码环境变量。
- 不改变 OCR Bearer、Basic 或代理协议。
- 不改变 OCR、翻译请求与漫画代理之间的代理边界。
- 不改变 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY` 行为。
