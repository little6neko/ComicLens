# 预先翻译当前章节进度设计

## 目标

预先翻译批次保留现有批次总进度条，并在“当前章节”区域增加与设置页单章后台翻译一致的阶段标签和章节进度条。批次仍然只展示当前正在处理的一章，不展开全部批次章节。

## 已确认的界面

采用可视化方案 A：完整复用单章任务的信息层级。

- 当前章节标题位于左侧。
- 右侧显示当前阶段：缓存与切分、等待开始、OCR、翻译、渲染、正在停止、处理中或等待重试。
- 标题下方显示章节进度条。
- 进度条下方显示已完成分片或图片数量、总数、百分比、源图缓存数量和失败数量。
- 尚未得到分片或图片总数时，使用现有动态进度条并显示“正在发现分片”。
- “正在让位给阅读器任务”提示继续保留；它不替代阶段标签。
- 现有“强制停止”操作继续保留，行为与位置层级不发生实质变化。
- 移动端允许阶段标签与辅助状态自然换行，不压缩章节标题。

## 数据模型

新增一个由单章任务和批次当前任务共同使用的进度快照模型。快照包含：

- `generationId`
- `status`
- `stage`
- `currentPageIndex`
- `currentSegment`
- `planningComplete`
- `totalPages`
- `preparedPages`
- `completedPages`
- `failedPages`
- `totalSegments`
- `completedSegments`
- `failedSegments`

`BackgroundTranslationTask` 在该快照基础上继续包含漫画、章节和任务类型等身份字段。`TranslationBatchTaskSummary` 复用同一快照字段。现有字段保持兼容，批次响应只新增 `stage` 和 `preparedPages`。

不新增数据库字段，也不需要迁移。所有数据均来自现有 `translation_generations`、`translation_pages` 和 `translation_segments` 记录。

## 后端数据流

翻译仓储提供按 `generationId` 读取进度快照的能力，并让批次任务与普通后台任务共用同一套阶段推导和字段映射逻辑。

1. 批次协调器取得当前批次项拥有的 `generationId`。
2. 翻译管理器从仓储读取该 generation 的进度快照。
3. 仓储根据 generation 状态以及当前 page 或 segment 状态推导 `stage`。
4. 仓储统计已缓存源图数量并填充 `preparedPages`。
5. 批次摘要把快照作为 `currentTask` 返回。

批次拥有的 generation 仍不出现在独立后台任务列表中；新增的是按明确 generation 读取快照的路径，不改变现有任务去重和隐藏规则。

## 前端复用

把设置页单章任务中以下逻辑提取为共享组件或共享辅助函数：

- 阶段中文标签和阶段徽标样式；
- 使用分片或整页作为进度单位的判断；
- 百分比计算和未知总数的动态进度条；
- 完成数量、源图缓存数量和失败数量的元信息。

设置页的单章任务继续使用共享展示，视觉和交互保持现状。预先翻译批次的当前章节区域使用同一个展示组件，因此后续阶段名称或进度规则变化不会产生两套实现。

批次详情页与设置页现有的一秒轮询保持不变，不增加接口数量或刷新频率。

## 状态与降级

- 有 `currentItem` 和 `currentTask`：显示阶段、章节进度条和完整元信息。
- 有 `currentItem` 但任务快照尚未建立：显示“等待开始”，并使用动态进度条。
- 批次让位给交互式阅读器任务：保留让位提示，同时显示当前任务快照中的阶段。
- 当前任务含失败项：在进度元信息中以错误色显示失败数量。
- 没有当前章节：不显示当前章节区域，保持现有批次总进度和操作按钮。

## 验证

后端测试覆盖：

- 按 generation 读取的快照能够返回 OCR、翻译、渲染等阶段；
- `preparedPages` 统计正确；
- 批次拥有的任务即使不出现在普通后台任务列表中，也能进入批次 `currentTask`；
- 批次接口以 camelCase 返回 `stage` 和 `preparedPages`；
- 现有批次调度、暂停、取消和恢复行为不变。

前端验证覆盖：

- 设置页单章任务改用共享组件后显示不变；
- 批次当前章节使用同一套阶段和进度展示；
- 未知总数、分片模式、整页模式、失败项和让位状态均有稳定布局；
- 桌面端与移动端布局不溢出；
- 格式检查、静态检查和生产构建通过。
