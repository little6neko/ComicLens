# ComicLens 分片渐进翻译与阅读器控制设计

## 目标

将现有“整张源图完成后发布”的翻译流程改为“整话预缓存、分片严格顺序翻译、每片完成即发布”，同时将阅读器调整为参考 `jm-boom` 的上下控制栏结构。

本次设计解决以下问题：

- 长图末尾的对白可能被 PaddleOCR 归类为图片块而没有 OCR 结果。
- 当前任务只按源图计数，无法从开始显示切分后的准确工作量。
- 当前源图必须全部切片完成后才显示译图，OCR 很慢时反馈不够及时。
- OCR、翻译或渲染失败只能按整张源图处理，不能只重试失败分片。
- 阅读器控制栏常驻且功能分散，不符合已确认的沉浸式阅读交互。

本文取代 `2026-08-13-async-ocr-deepl-design.md` 中“当前原图的全部 OCR 分片完成后才进入翻译”“按源图发布与重试”以及并发执行新翻译任务的相关约定。DeepL、DeepLX、语言、鉴权和其他设置设计继续有效。

## 已确认的产品行为

1. 开启实时翻译时，先持久化缓存本话全部源图并生成完整分片计划；计划完成后从一开始显示准确总数，例如 `0 / 33`。
2. 准备阶段只显示“正在准备本话”，不显示第二层下载进度。整项功能始终只有一个翻译进度。
3. 所有分片按源页序号、页内分片序号严格串行执行：当前分片完成 OCR、翻译、渲染和发布后才处理下一片。
4. 每个成功分片在写入缓存并提交数据库状态后立即显示，翻译进度同时加一。
5. 初次翻译的单片失败时保留该区域原图和“重新翻译此分片”按钮；重新翻译本话时若该区域已有旧译图，则旧译图继续作为可见底层。此前成功片不回滚，任务继续按顺序处理后续片。
6. 关闭实时翻译后，浏览器立即完整显示原图；后台仅完成当前分片并缓存，随后暂停。
7. 顶部显示分片翻译进度，例如 `18 / 33`；底部显示源图片阅读进度，例如 `3 / 9`。
8. 首次进入章节先显示上下控制栏；3 秒无操作或开始滚动后自动隐藏；点击漫画区域切换显示和隐藏。
9. 底部按钮顺序固定为：上一话、下一话、目录、阅读设置。
10. 漫画图片左上角不再显示“译图”角标。

## 术语与边界

- **源页**：上游章节清单中的一张原始漫画图片。底部阅读进度按源页计算。
- **显示分片**：源页中互不重叠、无间隙的一段纵向区域，是渐进发布和单片重试的最小单位。
- **OCR 裁片**：提交给 OCR 的图片。除首片外可在显示分片上方保留约 200px 上下文，因此 OCR 裁片之间允许重叠。
- **generation**：一次使用固定语义设置执行的整话翻译版本。重新翻译本话会创建新 generation。
- **发布**：译片文件已原子写入缓存，数据库已在事务中把该片标记为完成并设为可显示版本。

本次不改变现有长图切分默认值：最大 OCR 高度 8000px、目标高度 4000px、上下文重叠约 200px。修复图片块漏识别依靠 OCR 参数，而不是盲目减小 8000px 阈值。

## 整话准备与分片规划

### 准备顺序

翻译任务进入 `preparing` 后按章节清单顺序执行：

1. 获取并冻结本次任务的源页列表。
2. 将每张完整源图写入现有章节缓存包；已存在且校验通过的文件直接复用。
3. 清洗图片、读取宽高，并使用现有智能空白切分算法计算分片边界。
4. 在单个数据库事务中写入该 generation 的全部分片记录和总数，将 `planning_complete` 设为真。
5. 状态进入 `queued/running`，从全局顺序第一片开始 OCR。

任何 OCR 都不能早于全部源图缓存和全部分片计划提交。这样总数一旦出现就不再变化。若某张源图下载或校验失败，任务暂停在准备阶段，保留此前已缓存文件；再次开启后只补齐缺失源图并重新原子提交完整计划。准备阶段关闭翻译时，在当前网络请求安全结束后暂停，不启动 OCR。

冻结的源页快照按页保存受控来源 URL 和清单顺序。若准备阶段重启后缓存尚未补齐，优先复用快照；快照 URL 已失效时重新取得同一章节清单，并只按页序号更新仍未缓存页面的 URL。已缓存页面和已提交的完整分片计划不受后来上游清单变化影响。

### OCR 与显示边界

每个分片保存两组纵向坐标：

- `display_top/display_bottom`：该片独占的显示区域；相邻片首尾相接。
- `ocr_top/ocr_bottom`：实际 OCR 裁片区域；可向上覆盖前一片约 200px，用于保留跨边界文字上下文。

OCR 返回坐标先换算为源页全局坐标。文字块边界框中心点落在当前显示区域时才归当前片；最后一片包含源页最底边。这样重叠 OCR 不会造成重复翻译。渲染使用当前显示区域的原图和归属文字块，产物尺寸严格对应 `display_top/display_bottom`，因此浏览器覆盖层之间没有重叠或空隙。智能切线继续优先选择亮色空白区域，以降低文字框跨显示边界被裁断的概率。

### OCR 图片块参数

PaddleOCR 异步任务的 `optionalPayload` 固定为：

```json
{
  "useDocOrientationClassify": false,
  "useDocUnwarping": false,
  "useChartRecognition": false,
  "useOcrForImageBlock": true
}
```

`useOcrForImageBlock` 不作为用户设置，避免漫画对白因版面模型标记为 `image` 而被跳过。翻译语义指纹增加明确的流水线版本和 OCR 可选参数版本；旧参数生成的缓存不能匹配新 generation。OCR Token、DeepL Key 等密钥仍不进入指纹、API 响应或日志。

## 严格串行分片流水线

### 调度顺序

`TranslationManager` 在同一章节内始终只允许一个活动分片。待处理片按 `(page_index, segment_index)` 排序，并依次执行：

```text
读取 OCR 裁片
  → 提交或恢复 PaddleOCR 异步任务
  → 保存 OCR 原始响应与文字块
  → 调用当前 DeepL/DeepLX 服务
  → 保存译文检查点
  → 渲染无重叠显示译片
  → 原子写入缓存并发布
  → completedSegments + 1
  → 下一分片
```

不预先并发 OCR 后续片，也不并发翻译后续片。新流水线的有效分片并发固定为一。现有 OCR 并发设置继续保存在数据库和 API 中以保持升级兼容，但在严格顺序模式下不参与调度；设置界面应明确这一点。翻译并发仍可用于**当前分片内部**的 DeepL 批次或 DeepLX 文字块请求；执行器等待当前片的所有结果按输入索引稳定归并后才渲染，因此它不会造成分片乱序。

### 发布与进度

只有在以下条件全部满足后，分片才算完成：

1. 译片文件通过图片校验并以临时文件加替换的方式原子落盘。
2. 缓存索引已记录文件校验和与版本号。
3. 分片记录与活动显示映射已在同一数据库事务中提交。

浏览器轮询只会看到已发布版本，因此不会请求半写入文件。`completedSegments` 只统计成功发布片；OCR 完成、翻译完成或渲染尚未发布都不加一。失败片也不计入完成数，最终可显示 `32 / 33 · 1 失败`，任务状态为 `completed_with_errors`。

严格顺序指尝试顺序固定。某片最终失败后，调度器记录失败并继续下一片；因此后续片可以在失败片仍显示原图时完成，但绝不会在前一片仍处于执行状态时抢先处理或发布。

## 数据模型与持久化检查点

新增迁移，扩展 generation 汇总字段，并创建独立的分片记录。

### generation 字段

- `planning_complete`
- `total_segments`
- `completed_segments`
- `failed_segments`
- `current_page_index`
- `current_segment_index`

任务状态新增 `preparing` 和 `stopping_after_segment`。旧的 `stopping_after_page` 仅用于读取历史任务，不再由新执行器产生。

### `translation_segments`

主键为 `(generation_id, page_index, segment_index)`，并保存：

- 全局顺序、源页宽高；
- `display_top/display_bottom` 与 `ocr_top/ocr_bottom`；
- `pending/ocr/translating/rendering/completed/failed` 状态；
- OCR 裁片、OCR 原始响应、文字块、译文和译片缓存路径；
- PaddleOCR `job_id`，以及必要的远端结果定位信息；
- 译片版本号、尝试次数、失败阶段、错误代码和安全截断后的错误摘要；
- 创建和更新时间。

完整源图路径继续保存在页面记录中并复用现有 `/original` 媒体接口。OCR 裁片本身作为 `ocr_input` 缓存条目持久化，满足在 5GB 上限内长期保留原图和 OCR 图的要求。

页面记录补充准备状态、受控来源 URL、源图校验和及源图宽高。分片规划以源图校验和为输入；同一 generation 中校验和变化时必须废弃尚未开始的旧计划并重新生成完整计划，不能让一套边界对应另一份源图。

### 活动翻译图层

新增活动翻译图层映射，按漫画、章节、源页关联当前可见的整页旧译图或分片译图，以及各自的源图坐标、generation、路径、版本和层级。完整原图永远是最底层；旧 generation 的有效结果位于其上；当前 generation 每成功一片，就原子加入一个更高层级的译片。这样即使用户修改切片几何，新片也能按自身坐标立即覆盖旧结果，不要求新旧边界完全一致。

普通翻译和重新翻译都使用同一图层规则。当前 generation 全部成功后，各源页在事务中收敛为这一 generation 的完整分片集合，旧图层退出活动映射但缓存文件仍按 5GB 策略保留。若任务完成但存在失败，旧图层继续填补失败区间，新成功片保持在其上；没有旧结果的区间显示原图。媒体 API 返回从低到高排序的有效图层，前端不自行猜测新旧 generation 的优先级。

## 异步 OCR 恢复

PaddleOCR 提交成功后立即持久化 `job_id`，再开始轮询。状态恢复规则如下：

- 网络暂时失败或单次轮询超时不创建重复任务；在总超时范围内按现有退避策略继续。
- 达到本地总超时后，该片记为可重试 OCR 失败，但保留 `job_id`。
- 用户重试、进程恢复或服务重启时，先用已有 `job_id` 查询远端任务。
- 远端仍为 `pending/running` 时继续轮询；为 `done` 时下载结果；明确不存在、已失效或协议确认不可恢复时才清除 `job_id` 并重新提交。
- `failed` 状态保存云端错误信息，并允许该片重新提交。

服务启动时，异常中断前处于 `running` 的新 generation 恢复为 `queued` 并自动继续；处于 `stopping_after_segment` 的任务恢复为 `paused`，因为用户已关闭实时翻译。已完成片保持发布状态，当前片从最后一个完整检查点继续，不重复已保存的 OCR 或翻译调用。

## 失败、暂停与重试

### 分片失败

错误按 `ocr/translation/rendering/cache` 阶段记录。调度器捕获单片错误、增加 `failedSegments`，然后继续后续片。浏览器在失败显示区域保留底层原图；若该区间已有旧 generation 的有效译片，则重新翻译期间继续显示旧译片，直到新片成功覆盖。

单片重试接口根据失败阶段清理该阶段及之后的产物：

- OCR 失败：复用仍有效的 `job_id`，否则重新 OCR。
- 翻译失败：保留 OCR 裁片、OCR 响应和文字块。
- 渲染或缓存失败：保留 OCR 与译文。

重试把指定片重新置为待处理并唤醒 generation；多个重试请求仍按全局分片顺序执行。成功后错误信息清空、失败数减少、完成数增加，其他成功片不变。

### 关闭与恢复实时翻译

前端关闭开关时先更新本地显示状态并隐藏全部译图覆盖层，再发送暂停请求，所以网络延迟不会阻碍原图恢复。

- 没有活动分片时立即进入 `paused`。
- 正在准备时，当前源图请求安全结束后暂停。
- 正在 OCR、翻译、渲染或发布时进入 `stopping_after_segment`；当前片完整发布或失败后进入 `paused`，不开始下一片。
- 再次开启时复用已有计划与检查点，从全局最早的待处理片继续。

实时翻译的全局默认值继续保存在服务器设置中；阅读器内的开关只覆盖当前阅读会话，不反写全局默认。关闭仅控制显示和任务暂停，不删除任何缓存。

### 重新翻译本话

“重新翻译本话”保留确认步骤，并使用当前 OCR、翻译服务和语言设置创建新 generation。完整源图优先复用，重新生成并校验分片计划。旧活动译图在新结果尚未成功时继续显示；新 generation 每成功一片就以更高图层覆盖对应区域。重复点击同一次正在执行的重新翻译不得创建多个 generation。

## API 设计

现有翻译任务响应保留页面级字段以兼容旧前端，并新增：

- `totalSegments`
- `completedSegments`
- `failedSegments`
- `currentSegment`，包含页序号和页内分片序号
- 按源页分组、按分片序号排序的 `segments`

每个 segment 响应包含显示边界、当前 generation 的处理状态、尝试次数、新译片 URL（仅在该片成功后存在）和安全错误对象。每个源页另外返回 `translationLayers`：从低到高排序的当前有效整页或分片图层及其坐标、不可变版本 URL和 generation ID。重新翻译期间，新片仍在处理或失败时，旧图层继续有效；新片成功发布后追加在其上。没有有效图层的区域由浏览器显示原图。OCR 原始响应、缓存绝对路径、远端结果 URL、Token 和密钥不得返回。

新增或调整接口：

- `POST .../translation/start`：准备、开始或恢复任务。
- `POST .../translation/pause`：请求在当前分片边界暂停。
- `POST .../translation/retranslate`：确认后创建整话新 generation。
- `POST .../translation/pages/{page_index}/segments/{segment_index}/retry`：只重试指定片。
- `GET .../pages/{page_index}/segments/{segment_index}/translated?v=...`：返回不可变缓存译片。

旧页面级重试和整页译图媒体接口暂时保留，用于旧 generation；新前端只对新任务调用分片接口。版本参数必须与活动映射一致，避免越权读取任意缓存路径。

## 阅读器界面

### 显示层

每张源页使用一个相对定位容器：完整原图只渲染一次作为底图，有效翻译图层按服务端顺序和源图坐标绝对定位覆盖。整页旧译图覆盖完整区域，新成功译片位于其上。覆盖位置按 `display_top/source_height` 和区间高度比例计算，适配纵向、单页和双页模式的缩放。

开启译图时显示所有有效覆盖层；关闭时统一隐藏覆盖层。待处理或失败区域自然露出底图，无需再次下载、拼接或裁切原图。失败片在对应区域显示圆角提示和“重新翻译此分片”胶囊按钮；按钮阻止事件冒泡，点击不会误触控制栏显隐。

旧 generation 只有整页译图时，可继续使用整页译图作为翻译底层；新 generation 的成功译片覆盖其上。用户关闭译图后，整页旧译图和新译片都隐藏，只显示完整原图。

### 顶部控制栏

顶部使用半透明圆角浮层：

- 左侧圆形返回按钮。
- 中间显示漫画标题和当前话标题。
- 右侧为“译图开启/关闭”胶囊入口。
- 入口可控制实时翻译，并提供“重新翻译本话”操作及确认。
- 下方只显示一条分片翻译进度和 `completed / total`；有失败时追加失败数。
- 准备阶段显示“正在准备本话”，不展示源图下载子进度。

移除每张漫画图片左上角“译图”角标。翻译进度属于顶部控制栏，不放入底部阅读胶囊。

### 底部阅读胶囊

底部使用居中的半透明圆角胶囊，第一行是可跳转的源页阅读进度条和 `current / total`。纵向模式由可见面积最大的源页更新当前位置；单页和双页模式使用当前页组。拖动或点击进度条跳转到对应源页。

第二行只排列四个圆形按钮，顺序固定为：

1. 上一话
2. 下一话
3. 目录
4. 阅读设置

上一话和下一话按叙事顺序而不是 API 数组下标的表面方向定位：Manga18fx 详情返回的新到旧列表先归一化为旧到新阅读序列；上一话是该序列中当前话之前的较早章节，下一话是之后的较新章节。在两端分别禁用对应按钮，不通过标题字符串猜测章节号。目录从右侧抽屉打开、滚动并定位当前话。阅读设置包含纵向、单页、双页和翻页方向；服务器继续保存阅读设置。

### 控制栏显隐

- 首次进入章节时显示上下控制栏。
- 3 秒没有指针、触摸或键盘操作后自动隐藏。
- 纵向滚动或触摸移动开始时立即隐藏。
- 点击漫画区域切换显示与隐藏；所有控制按钮和失败重试按钮阻止冒泡。
- 目录抽屉、阅读设置或翻译操作面板打开时暂停自动隐藏计时并保持控制栏可见。
- 切换章节后重置为首次进入状态并重新开始计时。

所有纯图标操作使用正圆按钮，带文字的状态和动作使用胶囊按钮，不新增正方形按钮。

## 缓存策略

以下文件均进入现有章节缓存包并跨服务重启保留，不设按时间过期：

- 完整源图；
- OCR 输入裁片；
- OCR 原始响应与标准化文字块；
- 翻译结果；
- 渐进显示译片；
- 仍需兼容的旧整页译图。

全局默认上限继续为 5GB。超限时按章节包的最近最少使用顺序整话淘汰，避免留下无法恢复的半套状态。正在翻译的章节标记为活动，正在阅读的章节续租保护，均不能被中途淘汰；任务结束或阅读租约到期后恢复可淘汰。清除全部缓存或删除某话缓存时，文件、缓存索引、generation、页面记录、分片记录和活动映射必须保持级联一致。

这里的“永久保留”指没有 TTL、在 5GB 上限内持久化；达到上限后仍允许 LRU 淘汰。

## 兼容与迁移

- 现有已完成页面级译图和 display parts 继续可读，不进行批量重算。
- 新任务的语义指纹包含新流水线版本，因此不会复用 `useOcrForImageBlock=false` 的旧 OCR 结果。
- 旧的非终态 generation 不交给新分片执行器。用户再次开启时创建或恢复具有完整分片计划的新 generation；旧检查点保留到章节缓存被淘汰。
- 页面级 API 和字段先保留；待所有存量数据自然淘汰后再单独设计移除，不在本次范围内。
- 数据库迁移必须可重复启动、在事务中执行，且不得删除用户设置、源图或已完成译图。

## 组件边界

后端职责拆分为：

- `SegmentPlanner`：缓存整话源图、读取尺寸并生成确定性的分片计划。
- `SegmentRunner`：执行单片 OCR、翻译、渲染和发布；不负责章节调度。
- `TranslationRepository`：维护 generation、页面、分片、活动翻译图层和检查点事务。
- `TranslationManager`：串行调度、准备、暂停、自动恢复、单片重试和整话重译。
- `OCRClient`：提交、持久化标识并恢复 PaddleOCR 异步任务。
- 媒体 API：只通过活动映射和版本号提供原图或译片，不暴露文件系统路径。

前端将当前阅读器中的职责拆分为：

- 顶部阅读器控制和翻译状态；
- 底部阅读胶囊；
- 目录抽屉和阅读设置；
- 源页底图及译片覆盖层；
- 控制栏显隐状态；
- 失败分片及重试状态。

组件通过明确的任务状态和回调通信，避免继续扩大单一阅读器路由组件。

## 验证与验收

### 后端

- 全部源图缓存并校验完成前没有 OCR 请求；计划事务提交后总分片数准确且不再变化。
- 8000/4000/200 切分几何、显示区间连续性、OCR 重叠和文字块中心归属规则正确。
- PaddleOCR multipart 的 `optionalPayload` 包含 `useOcrForImageBlock: true`。
- 分片严格按 `(page_index, segment_index)` 串行，测试中的最大活动分片数为一。
- OCR、翻译或渲染完成但发布未提交时进度不增加；成功发布后只增加一。
- OCR 慢任务持久化 `job_id`；重试和服务重启优先继续轮询，远端任务明确失效后才重新提交。
- OCR、翻译、渲染和缓存失败分别从正确检查点重试，不删除更早的有效产物。
- 单片失败后继续下一片；最终汇总完成数、失败数和 `completed_with_errors` 正确。
- 暂停在当前分片完成后生效；准备阶段和无活动片时可以安全立即暂停。
- 异常重启恢复运行任务；已发布译片不重复处理。
- 整话重译去重；旧结果持续有效，新结果逐片原子替换。
- 5GB LRU 不淘汰活动或阅读租约内章节；整话淘汰和手动清理会同步级联状态。
- 旧页面级任务和媒体接口保持可读。

### 前端

- 准备阶段只显示单一状态；计划完成后顶部显示分片进度，底部显示源页进度。
- 每次轮询发现新完成片时只增加或更新该覆盖层，不等待整张源图或整话完成；服务端图层顺序决定新旧结果优先级。
- 关闭译图先本地隐藏整页译图和所有译片，即使暂停请求仍在网络中也立即显示原图。
- 失败片显示原图和单片重试按钮，成功片保持不变。
- 顶部、底部、目录和设置在移动端及桌面端均不遮挡关键操作。
- 首次显示、3 秒自动隐藏、滚动隐藏、点击切换和面板打开时保持显示均符合约定。
- 底部顺序严格为上一话、下一话、目录、阅读设置，边界章节禁用正确。
- 移除“译图”角标，所有新增按钮为圆形或胶囊形。
- 纵向、单页、双页和从左到右/从右到左模式均正确缩放和定位译片。

### 完整验证

运行数据库迁移测试、repository/manager/OCR/API 单元与集成测试、缓存恢复测试、前端测试、格式检查、lint、TypeScript 检查、生产构建及完整测试集。最后用真实长图验证：图片块中的英文对白可被 OCR；分片按顺序逐一出现；切换原图/译图无空隙、重叠或明显跳动；服务重启后任务能够继续。

## 不在范围内

- 不改变 Manga18fx 搜索、分类、排行、`Manhwa Raw` 或上游抓取逻辑。
- 不改变长图 8000/4000/200 的默认切分参数。
- 不增加分片并行、乱序发布或客户端 OCR。
- 不增加第二层源图下载进度、OCR 百分比或翻译批次进度。
- 不改变 DeepL 与 DeepLX 的服务选择、语言映射、鉴权或自动回退规则。
- 不立即删除旧页面级数据结构和接口。
