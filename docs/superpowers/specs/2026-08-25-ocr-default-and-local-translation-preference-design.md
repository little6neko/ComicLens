# OCR 默认并发与浏览器实时翻译偏好设计

## 背景

ComicLens 当前将 OCR 并发和“进入章节时默认实时翻译”都作为服务器设置保存。OCR 并发的
代码默认值为 `1`，而翻译并发默认值为 `2`。测试服务使用全新数据库时，因此会显示 OCR
并发为 `1`。

主题和默认阅读模式已经改为浏览器本地偏好，但默认实时翻译仍由 `/api/settings` 返回并通过
页面底部的“保存全部设置”提交。这使一个本质上属于阅读浏览器的偏好在所有设备之间共享，
也让它与主题、阅读模式的即时交互不一致。

本次将新安装的 OCR 并发默认值调整为 `2`，并把默认实时翻译彻底改为浏览器本地、即时生效
的偏好。已初始化数据库中的 OCR 并发不迁移；旧的服务器默认实时翻译值则在设置 schema
升级时直接丢弃，不复制到浏览器。

## 已确认行为

- 全新数据库的 OCR 并发默认为 `2`，有效范围仍为 `1–16`。
- 已有数据库中保存的 OCR 并发保持原值，包括值为 `1` 的数据库。
- “进入章节时默认实时翻译”只保存在当前浏览器，缺失或无效时默认关闭。
- 设置页切换该开关后立即更新浏览器偏好，不需要点击“保存全部设置”。
- 本地默认值只影响之后进入的章节，不启动或暂停已经打开的当前章节。
- 阅读器顶部的实时翻译开关继续只控制当前章节，不反写浏览器默认值。
- 同源标签页同步浏览器默认值；同步只改变以后进入章节时采用的默认值。
- 服务端完全删除默认实时翻译字段，不增加旧字段兼容或专用错误处理代码。
- 升级数据库时自动丢弃旧字段，其他已知服务器设置继续保留。

## OCR 并发默认值

`SETTING_DEFINITIONS["ocr_concurrency"]` 的默认值从 `1` 改为 `2`。该定义只用于新数据库、
缺失设置行或显式初始配置没有覆盖该值的情况。

本次不增加将现有 `1` 改为 `2` 的迁移。正常升级数据库已经包含 `ocr_concurrency` 行，通用
设置迁移会复制其原值，因此用户主动设置的值和历史默认值都不会被覆盖。OCR 限流器、动态
调整、全服务共享上限、任务顺序和缓存语义均不改变。

README、默认值测试和设置管理器测试同步将新安装默认值更新为 `2`。

## 浏览器偏好

新增独立的实时翻译默认值偏好模块，使用本地存储键：

`comiclens-realtime-translation-default`

存储和读取规则如下：

- 合法值只接受布尔语义的 `true` 和 `false`；缺失或无效值回退为 `false`。
- 读取、规范化、写入和订阅集中在偏好模块中，设置页和阅读器不直接访问存储键。
- 写入时先更新当前标签页的内存快照，再尝试写入 `localStorage`。
- 当前文档通过自定义事件通知所有订阅者；其他同源标签页通过浏览器 `storage` 事件同步。
- 浏览器拒绝访问 `localStorage` 时，当前标签页仍以内存值即时工作，但刷新持久化和跨标签
  同步不可用。

模块与现有阅读模式偏好保持相同的边界和容错方式，但不为两个布尔或枚举偏好引入新的通用
抽象，避免扩大本次重构范围。

改动完成后，只保存在浏览器中的配置共三项：

- 主题，沿用 `next-themes` 的 `theme` 键；
- 默认阅读模式，使用 `comiclens-reading-mode`；
- 进入章节时默认实时翻译，使用
  `comiclens-realtime-translation-default`。

登录会话仍保存在 HttpOnly Cookie 中，但它是认证状态而不是用户配置。

## 设置页交互

默认实时翻译开关从服务器设置草稿中移出，直接订阅浏览器偏好：

1. 用户点击开关；
2. 当前页面立即显示新值并写入浏览器偏好；
3. 同源其他标签页收到偏好更新；
4. 不发送 `/api/settings` PATCH，不显示服务器保存成功或失败提示；
5. 页面底部保存按钮只提交剩余服务器设置，也不会覆盖该浏览器偏好。

设置页说明更新为“主题、阅读模式和默认实时翻译保存在浏览器，其余设置保存在服务器”。开关
辅助文字明确它只影响之后进入的章节，当前章节仍由阅读器顶部开关控制。

## 阅读器行为

阅读器进入一个新章节时读取当时最新的浏览器默认值，并据此初始化当前章节的
`translationEnabled`：

- 默认值为开时，沿用现有逻辑启动或继续该章节翻译；
- 默认值为关时，先显示原图，不主动启动翻译；
- 同一章节打开期间，浏览器默认值发生变化不会修改当前章节状态；
- 切换到另一章节后，使用切换时最新的浏览器默认值；
- 顶部实时翻译开关继续立即控制显示以及后端任务的启动或暂停，但不修改浏览器默认值。

阅读器仍查询服务器设置以取得翻页方向及 OCR、翻译流水线所需配置。仅删除对服务器
`realtimeTranslationDefault` 字段的依赖。

## 服务端与数据库

从以下位置完整删除 `realtime_translation_default`：

- `SETTING_DEFINITIONS`；
- `ServerSettings` 响应模型；
- `ServerSettingsPatch` 请求模型；
- 前端 `ServerSettings` 和 `SettingsPatch` 类型及服务器设置草稿；
- 相关默认值、持久化和 API 测试数据。

设置 schema 版本从 `5` 提升为 `6`。升级时复用现有通用重建逻辑：先基于新定义建立默认
集合，再从旧数据中复制仍存在于 `SETTING_DEFINITIONS` 的已知字段，最后替换设置表内容。
由于默认实时翻译已不在定义中，其旧记录自然不会写回；OCR 并发和其他已知设置继续复制原值。

不新增字段专用的 `DELETE` SQL、迁移分支或兼容入口。`ServerSettingsPatch` 已配置
`extra="forbid"`，因此旧客户端继续提交 `realtimeTranslationDefault` 时会自然获得现有的
`422 VALIDATION_ERROR`。

全新数据库从一开始不会创建该设置记录。`COMICLENS_SETTINGS_JSON` 等初始设置即使仍包含旧
键，也会被现有“仅接受已知设置定义”的逻辑忽略。

## 错误与边界

- 本地存储值损坏时回退关闭，不让异常值进入 UI。
- 本地存储读写失败不触发服务器请求，也不阻塞当前标签页切换。
- 服务器设置读取失败时，浏览器默认值仍可在设置页显示和修改；阅读器仍需按现有方式处理
  其他服务器设置读取失败。
- 多标签页同步不会对已经打开章节调用启动或暂停接口。
- 页面底部保存失败不会回滚主题、阅读模式或默认实时翻译这三个浏览器偏好。

## 验证

后端测试覆盖：

- 全新数据库返回 OCR 并发默认值 `2`；
- 已有 schema 5 数据库中的 OCR 并发 `1` 在升级后仍为 `1`；
- schema 5 数据库升级后删除默认实时翻译记录，并保留其他普通及加密设置；
- `/api/settings` GET 不再返回 `realtimeTranslationDefault`；
- PATCH 携带旧字段由现有未知字段校验返回 `422`；
- OCR 并发运行时保存和动态调整行为保持不变。

前端与浏览器验证覆盖：

- 设置页开关立即更新本地值，不产生 PATCH 请求；
- 刷新后恢复本地值，缺失或损坏时默认为关闭；
- 两个同源标签页同步设置值；
- 已打开章节不因另一标签页修改默认值而启动或暂停；
- 进入新章节时采用最新默认值；
- 阅读器顶部开关不改变浏览器默认值；
- 保存其他服务器设置时请求体不含旧字段；
- 前端格式、Lint、类型检查、生产构建及完整后端测试通过。

## 非目标

- 不迁移或猜测旧服务器默认实时翻译值。
- 不把翻页方向、OCR、翻译服务、代理或缓存配置迁移到浏览器。
- 不改变当前章节实时翻译开关的任务启动、暂停或缓存行为。
- 不修改现有数据库中的 OCR 并发值。
- 不为删除的 API 字段保留兼容期。
