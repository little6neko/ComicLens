# ComicLens 章节打开即已读修复设计

## 目标

修复详情页和 Reader 章节目录看不到预期已读灰色的问题。ComicLens 改用与 `jm-boom`
一致的已读判定时机：Reader 成功取得当前章节 manifest，且 manifest 至少包含一页时，立即将
当前章节标记为已读。

这里的“打开”只要求章节 manifest 成功，不等待任何原图或译图下载、解码、渲染完成，也不要求
用户翻到或滚动到最后一页。

## 当前问题

详情页与 Reader 目录已经查询 `/api/comics/{comicId}/read-chapters`，也已经分别实现浅色、
深色和 Reader 固定深色画布下的已读样式。服务端已读接口及 SQLite 持久化同样正常。

问题在写入时机：Reader 当前只有在阅读位置到达最后一页时才调用 `setChapterRead`。因此用户已经
成功打开并阅读章节，但尚未到达最后一页时，服务端集合仍不包含该章节，两处现有灰色样式都不会
被激活。

## 与 jm-boom 的关系

`jm-boom` 并非路由一进入就记录已读。它在 Reader manifest 成功并得到 `pageCount > 0` 后，
先把章节 ID 合并进前端漫画状态缓存，再由阅读历史同步持久化。

ComicLens 照搬这个判定时机，但不照搬历史写入结构。ComicLens 已有独立的
`setChapterRead` API，应继续通过该接口持久化，阅读历史与已读集合仍保持现有职责边界。

## Reader 数据流

Reader 保留现有 manifest 查询和 `markRead` mutation，调整触发条件：

1. 进入或切换到一个章节；
2. manifest 查询成功；
3. manifest 计算出的 `totalPages` 大于零；
4. 当前这次连续进入尚未为该 `comicId + chapterId` 触发写入；
5. 立即乐观地把当前章节 ID 合并进 `readChapters` 查询缓存；
6. 调用现有 `setChapterRead(comicId, chapterId)`；
7. 成功后把服务端返回的完整 `chapterIds` 与当前缓存做单调合并。

移除“当前位置必须到达最后一页”的条件。重复渲染、页码变化、阅读模式变化和翻译进度变化不得
重复触发同一次进入的写入。用户离开后再次打开同一章节可以再次调用接口，由现有 upsert 更新
`read_at`，不会产生重复记录。

## 失败与竞态

- manifest 请求失败：不标记已读，因为这与 `jm-boom` 的判定语义一致；Reader 保持现有错误页。
- manifest 成功但页数为零：不标记已读。
- 已读接口失败：不阻断阅读；如果该章节原本未读，只从乐观缓存中移除本次失败的章节 ID，不回滚
  其他并发新增项；同时清除对应防重标记，使用户下次进入该章节可以重试。
- 已读集合查询与 mutation 并发：mutation 写入前取消该 comic 的在途已读查询，避免较早的查询
  响应覆盖乐观状态。
- 章节快速切换：mutation 显式携带目标 `comicId`、`chapterId` 和章节键，不依赖回调执行时的当前
  路由参数。成功响应只与当前缓存做并集合并，因此旧章节的较晚响应不能移除新章节状态。

已读写入仍是非阻断辅助行为，不新增提示框、加载遮罩或错误 toast。

## 显示规则

本次不重新设计章节列表：

- 详情页已读章节继续使用 `muted` 背景、`muted-foreground` 文字和弱化边界；
- Reader 目录中，已读且非当前章节继续使用 zinc 灰色背景、文字和边框；
- Reader 当前章节高亮优先于已读灰色；
- 不恢复勾号或增加“已读”文字；
- 浅色、深色与 Reader 固定深色画布均沿用现有可读配色。

这次缺陷的根因是已读集合没有在“成功打开”时写入，而不是主题变量或样式类丢失。修复数据时机后，
详情页和 Reader 目录复用同一查询缓存与服务端集合，自然保持一致。

## 范围

预计只修改 Reader 路由中的已读 mutation 与触发 effect；如实现需要，可新增一个只负责合并
`chapterIds` 的小型纯函数，避免重复和原地修改。

不修改：

- SQLite schema 与迁移；
- 已读 API 路径或响应结构；
- 阅读历史写入时机；
- 详情页和 Reader 目录布局；
- 章节排序、当前章节高亮和继续阅读逻辑；
- OCR、翻译、缓存和远程部署。

## 验证

实现后验证：

1. manifest 成功且至少一页时，不翻页也会将当前章节写入已读集合；
2. 不需要等待第一张原图或译图加载完成；
3. manifest 失败或零页时不写入；
4. 同一次进入不会因页码、模式或翻译状态变化重复写入；
5. 写入成功后 Reader 目录立即更新，返回详情页后同一章节保持灰色；
6. 当前章节在 Reader 目录保持高亮，其他已读章节为灰色；
7. 浅色和深色详情页均能区分已读与未读；
8. 已读写入失败不阻断阅读，下次进入仍可重试；
9. 完整后端测试、Ruff、前端格式检查、lint、TypeScript 和生产构建全部通过。

## 验收结果

用户成功打开一个有页面的章节后，该章节立即成为精确已读集合的一员。无论是否加载图片、是否
开启翻译、是否到达最后一页，详情页和 Reader 目录都能通过现有灰色规则区分它；加载失败或空
章节不会被误记为已读。
