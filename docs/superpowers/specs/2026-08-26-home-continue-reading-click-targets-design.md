# 首页“继续阅读”点击区域设计

## 背景

首页“继续阅读”卡片目前整体是一个指向阅读器的链接，右侧圆形书本图标只是链接内的装饰。因此点击封面、漫画名、章节名、进度条或卡片空白处都会直接进入阅读器，用户无法从该卡片进入漫画详情页。

## 目标

- 点击右侧圆形按钮时，继续打开历史记录中的章节和页码。
- 点击卡片内除该按钮外的任意位置时，打开对应漫画的详情页。
- 保持卡片尺寸、内容、进度展示和整体视觉风格不变。
- 两个点击目标都支持键盘操作并具有明确的无障碍名称。

## 非目标

- 不改变阅读历史、页码计算或历史接口。
- 不改变漫画详情页、阅读器路由或返回行为。
- 不修改历史记录页以及其他漫画卡片的点击行为。
- 不引入新的组件库或前端测试框架。

## 交互设计

卡片包含两个互不嵌套的链接：

1. 详情链接覆盖完整卡片，目标为 `/comic/$comicId`。
2. 右侧圆形阅读按钮位于详情链接上层，目标为 `/reader/$comicId/$chapterId`，并继续携带 `page = pageIndex + 1`。

因此，圆形按钮是唯一进入阅读器的区域；封面、标题、章节、进度、卡片边缘及按钮周围空白均进入漫画详情页。章节标题和进度信息只负责展示，不增加第三种点击行为。

## DOM 与无障碍设计

卡片外层改为非交互容器，详情链接和阅读按钮作为兄弟元素，避免产生嵌套链接或依赖事件冒泡拦截。

详情链接使用绝对定位覆盖卡片并保留圆角焦点轮廓；现有可视内容位于其上方但不截获指针事件。圆形阅读链接使用更高层级并恢复指针事件，使其覆盖详情链接。两者都使用 TanStack Router 的类型化 `Link`：

- 详情链接提供类似“查看《漫画名》详情”的 `aria-label`。
- 阅读按钮提供类似“继续阅读《漫画名》，第 N 页”的 `aria-label` 和 `title`。
- 图标继续作为装饰，不重复朗读。
- Tab 顺序先到详情链接，再到继续阅读按钮；Enter 分别执行对应导航。

卡片容器继续统一承载边框、背景、阴影和 hover 阴影。阅读按钮保留现有圆形主色样式，并增加与项目按钮一致的键盘焦点样式。

## 数据与异常边界

继续使用首页已有的第一条阅读历史 `recent`。不存在历史记录时仍不渲染“继续阅读”区域。路由参数继续使用历史记录中的 `comicId`、`chapterId` 和零基页码，不增加请求、状态或持久化字段。

本次变更只拆分导航目标，不改变加载失败处理；首页目录或历史查询原有行为保持不变。

## 验证与验收

- 运行前端格式检查、Lint、TypeScript 检查和生产构建。
- 在当前测试服务加载最新前端构建，确认卡片视觉没有明显变化。
- 点击封面、标题、章节、进度条和卡片空白处，均进入对应漫画详情页。
- 点击右侧圆形按钮，进入历史章节的 `pageIndex + 1` 页。
- 使用键盘依次聚焦详情链接和阅读按钮，确认 Enter 导航正确且焦点可见。
- 确认详情链接与阅读按钮没有嵌套，浏览器控制台无相关 DOM 警告。

## 验收标准

1. 只有右侧圆形按钮会从首页“继续阅读”卡片进入阅读器。
2. 卡片其他所有可点击区域都会进入该漫画详情页。
3. 阅读按钮仍准确恢复原章节和页码。
4. 鼠标与键盘交互均可用，卡片视觉和其他页面行为不变。
5. 前端格式检查、Lint 和生产构建全部通过。
