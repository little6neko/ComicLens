# 漫画详情页批量预先翻译设计

## 背景

ComicLens 当前只能从阅读器按话启动翻译。用户准备连续阅读一部漫画时，需要逐话进入阅读器才能创建任务，无法在漫画详情页一次选择多话并让服务在后台顺序处理。

现有 `TranslationManager` 已经完整负责单话的源图准备、长图切分、OCR、翻译、渲染、检查点、暂停恢复和失败重试。本功能不能复制这些能力，而应在其上增加跨章节的持久化编排。

## 目标

- 在漫画详情页主操作区增加“预先翻译”按钮。
- 支持全部章节、任意多选、连续区间和“从指定章开始”四种选择方式。
- 批量任务为一次性章节快照，不自动包含以后新增的章节。
- 对选中章节执行增量补齐：跳过完整成功项，继续暂停项，只重试失败项。
- 批量章节从旧到新执行，所有批量任务全局一次只运行一章。
- 批次关闭浏览器或服务重启后可以继续。
- 提供批次暂停、继续、取消剩余、重试失败章节和结束失败批次。
- 手动单话任务优先于批量预翻译任务。
- 详情页和设置页都能查看批次进度，设置页提供完整控制。

## 非目标

- 不实现定时任务或新章节自动订阅。
- 不重新实现 OCR、翻译、渲染、页面/分段调度或检查点恢复。
- 不增加批次级 OCR、翻译或代理设置。
- 不允许编辑正在执行的批次范围；需要等待、暂停后取消剩余，或关闭后创建新批次。
- 不在第一版提供批次历史页面、删除历史按钮或章节并发数设置。
- 不改变现有单话“全部重试”“重试失败”“暂停”和“强制停止”的用户语义。

## 已确认的用户语义

### 一次性批次

“预先翻译”只处理创建批次时存在并被选中的章节。漫画以后新增章节不会自动加入旧批次。

同一漫画最多存在一个未关闭批次。未关闭包括活动状态以及仍等待用户重试或结束的 `completed_with_errors`、`failed`。存在未关闭批次时，详情页按钮变成批次进度入口，不再打开新的范围选择器。其他漫画仍可创建批次；不同漫画的批次按创建时间进入全局批量队列。

### 章节选择

弹窗提供三个一级模式：

1. “全部”：选择当前漫画全部章节；
2. “指定章节”：通过复选框任意多选，并提供“选择区间”快捷操作；
3. “从指定章开始”：包含选中的边界章，以及目录中所有比它更新的章节。

连续区间使用目录顺序确定两个边界，不解析章节标题中的数字，因此特别篇、番外或非数字章节也能正确选择。应用区间后用该区间替换当前选择，用户仍可继续勾选或取消单个章节。

前端最终提交明确的 `chapterIds` 列表。服务端使用最新漫画详情验证 ID、去重，并依据上游目录顺序转换为从旧到新的执行顺序。选择为空时禁止提交。

### 增量补齐

某一章节轮到执行时：

- 完整成功：标记为跳过，不重新调用 OCR 或翻译；
- 正在执行：不创建重复任务，等待现有单话任务结束并采用其结果；
- 已暂停或整话失败：调用现有 `TranslationManager.start()` 继续；
- 存在失败项：调用现有 `TranslationManager.retry_failed()`，只恢复失败项；
- 从未开始：调用现有 `TranslationManager.start()` 创建任务。

批次本身不保存 OCR 或翻译设置。新单话任务在实际启动时读取当前设置；恢复既有 generation 时继续遵守现有单话规则：运行时 OCR 地址、协议和鉴权使用当前设置，generation 的语义快照继续由现有指纹与重试逻辑管理。

### 执行顺序与控制

- 所有批量批次共享一个调度槽，全局任意时刻最多有一章以“批量来源”运行；该章内部继续使用现有 OCR 并发。
- 批次中的章节从旧到新处理。
- 用户点击“完成本章后暂停”时，批次进入 `pausing`；当前章正常结束后变为 `paused`，不启动下一章。
- 用户点击“取消剩余”时，尚未开始的条目标记为取消；当前章正常结束后批次终止。
- 如需立即中断当前章，继续使用设置页现有的单话“强制停止”。
- 单章最终仍有失败项时，记录失败并继续下一章；批次结束为“有失败项”，提供“重试失败章节”。
- “重试失败章节”只把失败章节重新排入队列，成功和跳过的章节保持不动。
- `completed_with_errors` 或协调器自身 `failed` 状态提供“结束批次”。结束只关闭批次并允许创建新批次，不删除或改写底层单话 generation；这些章节以后仍可被新批次增量补齐。

### 阅读器任务优先

任何非批次拥有的手动单话任务都视为交互任务。交互任务开始时：

1. 已经发出的批量 OCR 请求不取消；
2. 批量当前章使用现有安全暂停能力，在当前分段结束后停止继续提交；
3. 交互任务使用现有全局 OCR 并发；
4. 所有交互任务结束后，如果批次仍为运行状态，则自动恢复原批量章节；
5. 如果用户同时手动暂停了批次，则不会自动恢复。

自动暂让原因与用户暂停原因必须分开记录，避免交互任务结束时错误恢复用户主动暂停的批次。

存在任意交互任务期间，整个批量调度器停止启动其他批次或章节。被暂让的批次继续占有批量调度位置，直到交互任务结束、当前批量章恢复并到达正常调度边界，防止另一个批次绕过阅读器优先规则。

## 架构

### 持久化薄调度器

新增 `PretranslationCoordinator`，职责仅限：

- 创建和恢复有序章节队列；
- 选择下一条目；
- 调用 `TranslationManager` 的公开单话操作；
- 观察单话终态并汇总结果；
- 管理批次暂停、取消剩余和失败重排；
- 在交互任务出现时协调批量当前章暂让。

协调器不得读取或修改翻译页面、分段、OCR Job ID、缓存路径，也不得复制 OCR/翻译重试规则。

### 现有单话管理器

`TranslationManager` 继续独占：

- 源图下载、缓存和切分；
- OCR 直接/异步协议与 Job 轮询；
- 翻译、渲染和发布；
- 页面与分段检查点；
- 单话暂停、恢复、强停和失败重试；
- generation 状态与运行时设置解析。

协调器只通过 `start`、`pause`、`retry_failed` 和状态读取等公开能力使用它。

为消除“单话 generation 已创建但批次条目尚未来得及关联”这一重启竞态，`TranslationManager.start()` 和 `retry_failed()` 增加可空的批次条目所有者参数。普通调用不传；协调器调用时传入当前 `batch_item_id`。Manager 必须在启动 worker 前把所有权与 generation 一起持久化。

### 活动通知

协调器需要被单话任务开始和结束事件唤醒，以便及时处理阅读器优先和下一章调度。通知只负责唤醒；真实状态始终从数据库读取，避免进程内事件丢失后产生错误状态。

## 持久化模型

### `translation_batches`

每行代表一次用户创建的批次：

- `batch_id`；
- `comic_id` 与漫画标题快照；
- `status`；
- `pause_reason`，记录用户暂停或配置错误；
- `interactive_yielded`，独立记录当前章是否因交互任务暂让；
- `error_code`、`error_summary`，仅用于批次级阻塞错误；
- `created_at`、`updated_at`。

批次状态：

- `queued`：等待全局批量槽；
- `running`：当前批次拥有批量槽；
- `pausing`：等待当前章完成后暂停；
- `paused`：用户暂停或配置错误暂停；
- `cancelling`：剩余条目已取消，等待当前章结束；
- `completed`：全部成功或跳过；
- `completed_with_errors`：存在失败章节，允许批量重试或结束批次；
- `cancelled`：取消剩余后的终态；
- `failed`：协调器自身出现无法继续的内部错误，允许继续排查后重试或结束批次。

使用数据库约束保证同一漫画最多一个未关闭批次。只有 `completed` 和 `cancelled` 视为已关闭；“结束失败批次”把批次改为 `cancelled`，但不改变其关联 generation。

### `translation_batch_items`

每行代表批次中的一章：

- `batch_item_id`；
- `batch_id`；
- `chapter_id` 与章节标题快照；
- 从旧到新的 `position`；
- `status`；
- `attempts`；
- `error_code`、`error_summary`；
- `created_at`、`updated_at`。

条目状态：`pending`、`running`、`completed`、`skipped`、`failed`、`cancelled`。

批次内对 `chapter_id` 和 `position` 分别建立唯一约束。批次完成数、失败数和跳过数从条目统计，不在批次表重复保存。批次条目不复制页面、分段或远端 OCR 状态。

现有 `translation_generations` 增加可空的 `batch_item_id` 所有权字段和相应外键，并对非空值建立唯一约束。它只用于标识当前 generation 是否由某个批次条目调度，不保存批次状态。一个批次条目任意时刻最多拥有一个 generation；若当前设置导致 Manager 创建新 generation，所有权在启动新 worker 前转移到新 generation。

## API

### 章节概览

`GET /api/comics/{comic_id}/translation-overview`

返回：

- 当前活动或待处理失败的批次摘要；
- 每个章节的本地翻译概览：未开始、活动、暂停、完整成功、存在失败或整话失败；
- 批次中的选中、当前和结果状态。

该接口一次查询所有章节状态，前端不为每一章发送独立请求。

### 创建批次

`POST /api/comics/{comic_id}/translation-batches`

请求：

```json
{
  "chapterIds": ["chapter-1", "chapter-2"]
}
```

服务端重新读取漫画详情，验证所有 ID、去重并按旧到新排序。空选择、未知章节或超过 5000 章返回 `422`。已有未关闭批次返回 `409` 并携带稳定错误码，前端随后打开现有批次。

服务端先计算增量工作量。如果所有选中章节都已完整成功，返回“无需处理”的成功结果，不创建空批次，也不要求 OCR 或翻译服务已配置；只有确实存在待处理章节时才验证当前服务配置并创建批次。

### 批次列表与操作

- `GET /api/translation-batches/background`：返回活动批次和仍有失败项的终态批次；
- `POST /api/translation-batches/{batch_id}/pause`；
- `POST /api/translation-batches/{batch_id}/resume`；
- `POST /api/translation-batches/{batch_id}/cancel-pending`；
- `POST /api/translation-batches/{batch_id}/retry-failed`；
- `POST /api/translation-batches/{batch_id}/close`，仅关闭 `completed_with_errors` 或 `failed` 批次。

操作接口返回更新后的批次摘要。暂停、继续、取消剩余和结束批次保持幂等。批次 ID 与漫画 ID 不从前端标题推断。

`resume` 接受用户暂停、配置错误暂停和可恢复的协调器 `failed` 状态；继续前重新验证配置与状态一致性，验证仍失败时返回 `409` 并保留原状态。`close` 不接受仍在运行的批次，运行中应使用 `cancel-pending`。

## 调度与恢复

### 正常调度

协调器按批次创建时间寻找第一个可运行批次，再按 `position` 寻找第一个 `pending` 条目。调用单话入口时传入 `batch_item_id`；Manager 在启动 worker 前持久化 generation 所有权。协调器按该所有权找到实际 generation，等待它到达终态，然后在事务中更新条目与批次状态并唤醒下一轮。

`TranslationManager.start()` 本身对同漫画/章节具有复用语义。所有权与 generation 创建或恢复在 worker 启动前提交，因此进程在任何时点退出都能由协调器找到同一个 generation，不依赖漫画/章节猜测，也不创建重复任务。

### 服务重启

现有 `TranslationManager` 自动恢复查询必须排除 `batch_item_id` 属于未关闭批次的 generation，防止批量章节绕过全局批量槽自行启动。普通单话 generation 继续按原逻辑自动恢复。

协调器启动后：

1. 重新读取所有非终态批次；
2. 按 `batch_item_id` 核对 `running` 条目所有 generation 的真实状态；
3. 已完成则提交条目结果；
4. 未完成且批次允许运行，则通过现有单话入口恢复；
5. `pausing`、`cancelling` 和用户 `paused` 状态保持原语义；
6. 恢复后仍保证全局只有一个批量章节运行。

### 配置错误

确认存在实际待处理章节后、创建批次前验证当前 OCR 与翻译服务配置。运行期间若配置被清空或变为无效，协调器在启动下一章前将批次暂停并保存安全错误摘要，不把所有剩余章节标记失败。用户修正设置后点击继续。

### 章节错误

源站、OCR、翻译、渲染或缓存错误继续由现有单话逻辑分类和重试。单话到达失败终态后，协调器把对应条目标记为失败并继续下一章。批次级数据库或内部一致性错误才把批次标记为 `failed`，防止形成高频重试循环。

## 前端设计

### 入口

“预先翻译”按钮位于漫画详情主操作区，与“继续阅读”“收藏”并列。

- 无未关闭批次：显示“预先翻译”；
- 排队或运行：显示 `预先翻译 X / Y` 和活动指示；
- 暂停：显示“预先翻译已暂停”；
- 批次有失败：显示“预先翻译有失败项”。

有未关闭批次时点击按钮打开批次详情，而不是创建第二个批次。

### 范围选择弹窗

- 桌面端使用居中弹窗；
- 移动端使用全屏弹窗，不缩小桌面布局；
- 标题和底部确认区固定，章节列表单独滚动；
- 底部显示“已选 N 话 · 实际补齐 M 话”；
- 完整成功章节显示为将跳过，失败章节显示为将重试；
- 没有实际工作时禁用开始按钮并显示“无需处理”；
- 创建前明确说明后台按旧到新、一次一章执行。

“指定章节”模式提供搜索、逐章复选和“选择区间”。“从指定章开始”使用章节选择器，文案不得回退为“从本章开始”。

### 详情页批次详情

批次详情显示：

- 批次状态与章节总进度；
- 当前章节及其现有单话阶段、页/分段进度；
- 完成、跳过、失败和取消数量；
- 暂停/继续、取消剩余、重试失败章节；
- `completed_with_errors` 或 `failed` 状态下的“结束批次”。

### 设置页后台任务

设置页“后台 OCR 翻译”区域增加批次卡：漫画标题、批次状态、当前章、章节总进度、结果汇总和控制按钮。

由未关闭批次拥有的当前单话任务嵌套显示在批次卡中，不再同时渲染为另一张独立任务卡。普通阅读器任务继续使用现有单话卡片。成功完成且无失败的批次从后台区域移除；`completed_with_errors` 批次保留到失败章节解决或用户主动结束。结束批次后，底层失败 generation 仍可按现有单话规则出现在后台任务区。

## 日志与安全

新增批次事件日志：创建、开始条目、跳过、条目完成、条目失败、暂停请求、交互暂让、恢复、取消剩余、批次完成和恢复核对。

日志使用缩短的 `batch_ref`、现有 `generation_ref`、漫画/章节标识、条目位置、状态和安全错误码。不得记录图片内容、OCR/翻译响应正文、Token、Basic Auth、代理密码或完整远端 Job ID。

章节标题快照仅用于界面展示；所有源站调用继续遵守现有漫画代理规则，OCR 与翻译继续使用现有 HTTP 客户端和环境变量行为。

## 测试设计

### Repository

- 批次与条目创建、旧到新顺序和唯一约束；
- 所有批次/条目状态迁移；
- 暂停、取消剩余、失败重排、结束失败批次和汇总计数；
- 重复动作幂等；
- 事务失败完整回滚。

### Coordinator

- 三章严格按旧到新执行，任意时刻只有一个批量章节；
- 多本漫画批次按创建时间共享一个批量槽；
- 完整成功跳过、暂停继续、失败项重试和新任务创建分别调用正确的单话入口；
- 单章失败后继续下一章；
- 用户暂停等待当前章完成，取消剩余不打断当前章；
- 失败章节重排不影响成功和跳过条目；
- 交互任务使批量章在当前分段后暂让，并只在允许时自动恢复；
- 交互任务期间不启动其他批次，用户暂停意图与交互暂让可以同时存在；
- 每章启动时使用当前运行时设置，不使用批次创建时的设置快照。

### 恢复与竞态

- 服务在单话启动前后、OCR 中、交互暂让、`pausing` 和 `cancelling` 状态重启；
- 批次 generation 不被现有自动恢复逻辑抢先启动；
- generation 所有权在 worker 启动前持久化，不存在未关联窗口；
- generation 因设置指纹变化而替换时，批次所有权正确转移；
- 重复创建、暂停、继续、取消和失败重试保持幂等；
- 配置失效只暂停批次，不批量生成失败条目。

### API

- 全部、任意多选、连续区间和“从指定章开始”解析为正确章节列表；
- 边界章包含在“从指定章开始”范围中；
- 未知、重复、空章节 ID、超过 5000 章和未关闭批次冲突返回稳定错误；
- 概览接口一次返回章节状态与当前批次；
- 后台接口隐藏成功批次并保留有失败项批次；
- 响应使用现有 camelCase 规则。

### 前端与回归

- 桌面居中弹窗与移动端全屏弹窗；
- 三种一级模式、搜索、任意多选、区间替换和边界选择；
- 选择摘要、无任务状态和请求中禁用；
- 详情页按钮的排队、运行、暂停和失败状态；
- 设置页批次卡控制以及当前单话任务去重；
- 键盘导航、焦点锁定、关闭后焦点恢复、`aria-label` 和窄屏滚动；
- 完整 pytest、Ruff、前端格式检查、Lint、TypeScript 检查和生产构建通过。

## 验收标准

1. 用户可以在详情页一次创建全部、任意多选、连续区间或从指定章开始的持久化批次。
2. “从指定章开始”包含边界章，执行顺序始终从旧到新。
3. 完整成功章节不重复处理；暂停、失败和未开始章节按既有单话语义增量补齐。
4. 所有批量任务全局一次只运行一章，手动单话任务能够安全暂让并优先执行。
5. 浏览器关闭和服务重启后，批次不丢失、不重复创建 generation，也不绕过批量调度槽。
6. 详情页和设置页都显示准确批次进度；设置页支持暂停、继续、取消剩余、重试失败章节和结束失败批次。
7. 桌面和移动端布局、交互与无障碍行为符合已确认方案。
8. 单话翻译、失败重试、强停、缓存和 OCR 协议行为没有回归。
9. 后端与前端全部自动检查通过。
