# 首页“继续阅读”点击区域实施计划

依据：`docs/superpowers/specs/2026-08-26-home-continue-reading-click-targets-design.md`

## 阶段 1：拆分详情与继续阅读导航

- 修改 `web/src/routes/_app/index.tsx`，将当前包裹整张卡片的原生阅读器 `<a>` 改为非交互卡片容器。
- 增加覆盖卡片的 TanStack Router `Link`：
  - 路由为 `/comic/$comicId`；
  - 使用 `recent.comic.comicId` 作为类型化参数；
  - 提供漫画详情无障碍名称和覆盖整卡的键盘焦点样式。
- 将右侧圆形书本图标改为独立的 TanStack Router `Link`：
  - 路由为 `/reader/$comicId/$chapterId`；
  - 使用历史记录中的漫画、章节参数；
  - 搜索参数继续传递 `pageIndex + 1`；
  - 提供继续阅读无障碍名称、提示文字和可见焦点样式。
- 使用兄弟链接、层级和指针事件保证圆形按钮覆盖详情链接，不产生嵌套交互元素或依赖 `stopPropagation`。
- 保留封面、标题、章节、进度条、边框、阴影和响应式尺寸。

## 阶段 2：静态验证与构建

- 运行 `cd web && npm run fmt`，只接受目标文件的机械格式化。
- 运行：
  - `cd web && npm run fmt:check`
  - `cd web && npm run lint`
  - `cd web && npm run build`
- 检查 `git diff --check` 和目标文件 diff，确认：
  - 两个链接为兄弟元素且路由目标正确；
  - 只有圆形按钮链接保留阅读器目标和历史页码；
  - 其余覆盖区域只链接到漫画详情；
  - 没有无关文件变化。

## 阶段 3：测试服务验收

- 继续使用当前 `0.0.0.0:8233` 测试服务和临时数据目录；生产构建更新后确认 `/health` 与首页可访问。
- 确认最新构建产物已由测试服务加载，首页“继续阅读”卡片视觉结构完整。
- 核对鼠标和键盘语义：详情覆盖链接先聚焦，圆形继续阅读链接后聚焦，二者具有不同的无障碍名称。
- 记录无法在无浏览器自动化环境中代替用户完成的实际点击验收，并保留测试服务供用户检查。
- 提交业务代码改动，报告验证结果和测试服务状态。
