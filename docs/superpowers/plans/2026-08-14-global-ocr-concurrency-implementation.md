# ComicLens 全服务动态 OCR 并发实施计划

## 目标

按已确认的设计，让服务器设置 `ocr_concurrency` 成为所有章节共享、运行时可调整的
PaddleOCR 生命周期上限。默认值保持 `1`；OCR 可以并发预取，翻译、渲染和发布继续按
`global_index` 严格串行。

## 阶段 1：可动态调整的共享限流器

- 新增独立异步限流组件，支持获取、释放、FIFO 等待和运行时调整 `1–16` 上限。
- 调高上限时立即放行新增槽位；调低时保留既有许可并阻止后续放行。
- 取消、异常和正常完成统一通过异步上下文管理器释放许可。
- 让 `OCRClient` 可接收共享限流器；未注入时保留私有限流行为，兼容直接构造和旧流水线测试。
- 增加限流器单元测试：默认串行、最大活动数、动态升降、取消释放及 FIFO 顺序。
- 运行 OCR/算法相关测试并提交。

## 阶段 2：可恢复的 OCR 阶段拆分

- 将 `SegmentRunner` 拆为“OCR 检查点准备”和“按序翻译—渲染—发布”两个公开边界。
- OCR 阶段负责缓存命中、远端 `job_id` 恢复、响应与文字块落盘；成功后把分片恢复为带
  `ocr_path/blocks_path` 的待处理状态。
- 顺序阶段只读取已经校验的 OCR 检查点；现有完整 `process` 组合两个阶段以兼容调用者。
- 为仓储增加原子认领 OCR、标记 OCR 就绪、取消后恢复待处理以及按顺序查询未终结分片的接口。
- 保留现有分片失败代码、重试清理范围和缓存路径，不增加数据库迁移。
- 增加缓存命中、作业恢复、取消和 OCR 失败隔离测试并提交。

## 阶段 3：章节预取协调器与全服务调度

- `TranslationManager` 启动时用持久化 `ocr_concurrency` 创建唯一共享限流器。
- 渐进 generation 为已持久化分片维持有界 OCR 预取窗口，不把整章一次性排入等待队列。
- 切片生产者每追加一页即唤醒协调器；协调器并发准备 OCR，顺序消费者只对最小
  `global_index` 执行翻译、渲染和发布。
- OCR 乱序完成时保存检查点但不提前增加进度；失败片记录错误后允许后续 OCR 继续。
- 普通暂停停止补充预取、完成当前顺序片并取消后续本地轮询；强制停止立即取消全部本地协程。
- 服务恢复和分片重试复用检查点或 `ocr_job_id`，并重新竞争共享许可。
- 增加单章最大并发、双章全局上限、乱序 OCR/有序发布、动态分母、暂停、强停、恢复和失败测试。
- 运行翻译管理器测试并提交。

## 阶段 4：设置运行时生效与界面说明

- 为 `TranslationManager` 增加运行时调整接口，并唤醒所有活动预取协调器。
- 设置 API 只有在持久化成功后才调整内存上限；相同值不触发额外调度。
- 更新设置页 OCR 并发辅助文字，明确“全服务上限、保存后立即生效”。
- 保持默认 `1`、范围 `1–16`、服务器持久化和“保存全部设置”交互不变。
- 增加设置 API 的运行时升降测试及前端静态检查并提交。
